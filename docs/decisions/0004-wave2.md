# ADR 0004: Wave 2 isolated feature foundations

Accepted 2026-10-12. Baseline: 08f6daa (confirmed origin/main).
Coordinator: Codex root; three implementation workers, one writer per task.
Each task uses its own worktree, branch, claim/handoff and draft PR. No merges.
The unrelated original worktree and untracked .claude/ remain untouched.

## Ownership and sequence

R1 sessions review → R9 analytics: worker A.
R2 selected-file watcher → R3 desktop workflow: worker B.
R4 Lua evaluator/HUD → R11 Lua gear: worker C.
Then workers take R5 planner, R6 acquisition, R7 content persistence,
R8 content CLI and R10 atlas navigation as slots become available.
R12 integration CI/browser checks follows their dependencies.
Root owns shared manifests, lockfiles, core module exports, generated contracts,
CI configuration and integration documentation. Workers request shared changes.
No exchange schema changes. Planner and analytics remain library types.
R7 is the sole storage implementation writer; R3 only consumes snapshot APIs.

## Frozen interfaces

Watcher: one explicitly selected path, existing FileFormat/ImportOptions;
500 ms polling and 750 ms unchanged size/mtime; bounded existing importer;
fixed status codes and cancellation; failed partial reads retried.
Desktop: explicit application DTOs for text/file import, start/stop watch,
profile selection, profile list, current snapshot and history. Profile IDs
resolve server-side to the complete ProfileKey (character, edition, build,
interface, namespace, fixture). Preserve stored/duplicate/history-only reasons,
fixture/demo status and freshness. SQLite/normalization run off the UI thread.
No live state or addon socket. Reference pins remain separate from unlocks.

## Acceptance

Each package runs affected tests, formatting, locked Clippy/workspace tests,
contract drift checks and relevant Lua/desktop checks. Record actual commands
and results, then hosted CI on its draft PR. Synthetic fixtures only. Live WoW,
native interaction and packaging remain unverified. No release/publication or
PR merge is authorized. Dependencies use stacked branches when necessary;
each PR names its prerequisite and contains only its task diff.

## Execution record

Worker A implemented R1/R9/R7 and reviewed R5/R6; worker B implemented R2/R3,
reviewed/corrected R10; worker C implemented R4/R11. Root implemented R5/R6/R8/R10,
owned shared dependency/export changes, corrected age refresh and completed R12
and integration documentation. Review corrections transferred task ownership
explicitly; no simultaneous writers. Baselines and accepted checks are in each
handoff and the final integration record.

"No merges" above means no PR/main merges. Local feature branches were combined
in `integration/wave2-foundations`, with a scoped R12 PR stacked on that branch;
the final documentation PR is stacked on R12. Published history is preserved.
The original worktree and .claude/ directory remain untouched.

## Authorized merge completion

The user subsequently authorized marking all open PRs ready after CI and merging
in dependency order. This supersedes the implementation-phase no-merge scope.
Protected main updates, full current-head CI gates, merge commits and retained
branches preserve history. See the 2026-10-12-wave2-merge handoff for the audit.
