# Review: G6 design-system follow-ups (PR #163, head 533228b)

Reviewer: Claude Code (Sonnet 5.5), read-only, own worktree, detached at origin/feat/g6-followups.
Base compared: `origin/main...HEAD` (b60193e). Nothing pushed or modified except this file.

## Verdict

No blockers. One important finding (the text-over-backdrop fix does not reach the reference window)
and several optional items. The accessible-name migration is sound.

## Findings

### Important

**I1. The 90% sheet covers only `.app-shell`; the reference window still has text directly on the backdrop.**
`apps/desktop/src/theme/base.css:82` puts the sheet on `.app-shell`. `src/main.tsx:16-19` renders `<Backdrop />`
for `#reference` too, but wraps it in `.reference-shell` (`base.css:83`, padding only), and `ReferenceView.tsx`
uses no `Panel` (0 occurrences) or other filled surface, just a `<section>` with plain `h2`/`p`. Its body text
and muted text sit on raw backdrop art. `composite.test.ts` ("text over the backdrop") reads only the
`.app-shell` rule, so the G4 #5 bound is proven for the main window and silently absent for the second
window. The handoff and `tokens.css` note present #5 as resolved without that limitation.
Failure scenario: backdrop colours up to `#e6c66a` / `#e08a4a` (at 0.45 ember opacity, or opaque as the test's own
worst-case model) under `--text`/`--text-muted` in the reference window fail 4.5:1.
Fix: give `.reference-shell` the same sheet (`background: color-mix(in srgb, var(--surface) 90%, transparent)`,
plus the high-contrast `var(--surface)` and forced-colours `Canvas` overrides), and make the composite test
iterate over both selectors; or document the limitation in the handoff.

### Optional

**O1. Nested-panel e2e does not require nested panels to exist for five of the six screens.**
`e2e/nested-panel-reflow.spec.ts` asserts `nested.length > 0` only for the Party test. For Compatibility,
Content, Atlas, Gear, Planner, Sessions and Dungeons the loops over `result.nested` pass vacuously if a screen
has no (or stops having) nested panels; the "padding 0 / shadow none" assertions are then unexercised. The
title claims "(both have nested panels)". Fix: add `expect(result.nested.length).toBeGreaterThan(0)` per screen
that is known to nest, or list which do.

**O2. Nested detection is a plain React context boolean.** `ui/Panel.tsx:11,19-29`. It is correct for real
nesting and sibling panels (verified by `followups.test.tsx`). Behaviour to be aware of: context crosses
portals, so a Panel rendered in a portal or modal opened from inside a Panel would be styled nested (flat, no
frame). No portal or modal currently renders a Panel (grep of `src`), so no false positive today. Fix if a
dialog is added: wrap the portal content in `<InsidePanel.Provider value={false}>`.

**O3. Container-query fallback is graceful but untested.** `base.css:82,95`. Without container-query support
the `@container` block is skipped and the wrapping bar is always used (usable). `container-type: inline-size`
gives `.app-shell` layout containment, so it becomes the containing block and stacking context for fixed
descendants; no `position: fixed` descendant exists (only `.backdrop`, outside the shell), so nothing breaks
now. Rail threshold is 58em of shell content width (about 928 px of content, a 960 px window at 100% text;
the handoff states this). Not covered by a test: a viewport at the threshold, and the unsupported-engine
path. No `@media print` rules exist anywhere (pre-existing), so print is unchanged; the sheet will not print
as a background by default, which only helps.

**O4. Pressed Button is styled by a (0,2,0) rule.** `ui/ui.css:50`. It beats variant box-shadows and, in
forced colours, the `@media (forced-colors)` button rule (0,1,0) on `box-shadow`/border colour; the engine's
forced-colour substitution makes this harmless, and bold plus underline remain as non-colour cues. In high
contrast it applies a gold border on `--surface`, readable. No test renders `aria-pressed` styling in high
contrast or forced colours. The `"aria-pressed"` member added to `ButtonProps` is redundant (already in
`ButtonHTMLAttributes`), harmless.

**O5. Replacing native buttons with `Button` adds margin.** `src/screens/play.css:19` `.play-screen .ui-button { margin: ... }`
now applies to the Atlas pin buttons and route hop buttons, shifting their layout slightly. Focus management
is intact (ref callbacks and `onKeyDown` unchanged; Atlas and route e2e pass).

**O6. HelpTip "Help: label" with odd labels.** `ui/HelpTip.tsx` sets the string in `aria-label` directly, so
special characters (parentheses, commas, quotes) need no escaping. Duplicate Field labels on one screen give
duplicate "Help: X" names (previously every tip was "Help", so strictly better). Empty-string label falls back
to "Help". The `getByLabel(..., { exact: true })` changes keep the same string and exactly match the control
label, so assertions are stricter, not weaker. Four wrapping labels intentionally stay inexact (listed in the
handoff). Residual risk: `toHaveCount(0)` / `not.toBeVisible` assertions that now use `exact` can pass
vacuously if the label text changes later; that risk existed before.

**O7. STATUS.md.** `docs/STATUS.md` is accurate against the actual PRs (#160 G4, #161 G5a, #162 G5b, #163
draft/open, 0.9.1 still the latest published, tag `v0.9.1`). It cites "earlier tasks in PRs #157 to #159";
G2b was PR #156 (`test/g2b-native-smoke`), also merged, so the range is incomplete. The claim file names a
worktree path of a different agent id than this PR's author; cosmetic.

**O8. Resize clamp.** `HelpTip.tsx` `measure`/layout effect: listener added only while open and removed in
the effect cleanup; `measure` does not set state in a loop (it computes from `box.left - shiftNow` and writes
the same value if unchanged, so React bails out). A hidden bubble has width 0 and returns early. No loop found.
The test "stops listening for resize once closed" only asserts that some `removeEventListener("resize")` call
happened, a weak check; the resize re-measure test does fail without the change.

### Checked and fine
