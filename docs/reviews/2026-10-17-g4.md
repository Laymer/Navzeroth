# Review: PR #160, task G4 (desktop design system, original backdrop, app shell)

Reviewer: Claude Code (Sonnet 5.5) review agent, read-only. Head: origin/feat/g4-design-system. Base: origin/main (a6e6ab3).
Severity scale: plan 21.6 (blocker / important / optional).

Verdict: no blockers. Fonts, hashes, CSP, backdrop originality and the Rust change check out. Three accessibility items
(primary button contrast, HelpTip announcement/dismissal, high-contrast text selection) should be fixed or explicitly
accepted before G5 builds on these primitives.

## Findings

### Important

1. **Primary button text fails 4.5:1 over most of its gradient** - `apps/desktop/src/ui/ui.css:30` (gradient `--ember-hi`, `--ember` at 55%, `--ember-shade`); only pair declared is `apps/desktop/src/theme/tokens.css:19` (`--on-ember on --ember`).
   Scenario: white text sits on `linear-gradient(#cf7650, #b15838 55%, #6e311b)`. White on `--ember-hi` is 3.30:1; at the text's vertical middle (blend of ember-hi and ember, about #c06744) it is about 3.99:1. Only the flat `--ember` (4.86:1) is tested, so the contrast test passes while the real rendering fails SC 1.4.3. The only current use is "Retry loading", but G5 will use `Button variant="primary"` widely. The 1px text-shadow does not count.
   Fix: start the gradient at `--ember` (or darken `--ember-hi`) and declare `--on-ember on --ember-hi` in tokens.css so every stop the gradient uses is tested.

2. **HelpTip content is not announced when opened; Escape cannot dismiss hover-only help** - `apps/desktop/src/ui/HelpTip.tsx:66-87`.
   Scenario A (toggletip semantics): activation sets `aria-expanded` and `aria-describedby` on the already-focused button. `aria-describedby` is read when focus lands, not when it is added afterwards, and the bubble has no live region (the handoff deliberately avoids `role=status`). A screen-reader user who presses Enter hears at most "expanded" and may never hear the help text. The toggletip pattern writes the text into a persistent live region on activation. This is reasoned from the ARIA model; no screen reader was run.
   Scenario B (SC 1.4.13 dismissible): `onKeyDown` is only on the trigger. A pointer user who hovers the "?" while focus is elsewhere sees the bubble open and Escape does nothing; only moving the pointer away dismisses it.
   Fix: A, keep an always-mounted visually hidden `aria-live="polite"` span that receives the text when the tip opens by click/focus (revisit the status-role ban with a real AT check). B, add a document-level `keydown` Escape listener while `open`.

3. **`::selection` is unreadable in high-contrast mode** - `apps/desktop/src/theme/base.css:11` (`::selection { background: var(--gold-shade); color: var(--text); }`).
   Scenario: with `data-contrast="high"`, `--gold-shade` is #ffd54a and `--text` is #ffffff, a 1.41:1 pair (computed). Selecting text, which high-contrast users do to read and copy, makes it vanish. The pair is undeclared, so the contrast test cannot catch it. Default mode is fine (5.24:1).
   Fix: add `--selection-bg` / `--selection-fg` tokens, declare them in the `contrast:` comments, and make high contrast black text on gold (or the reverse).

### Optional

4. **Rail breakpoint ignores the Settings text scale** - `apps/desktop/src/theme/base.css` (`@media (min-width: 60rem)`).
   Text scale is applied as `html { font-size: N% }`. In media queries `rem` is the browser's initial 16px, not the root size, so at 200% text a 1100px window still gets the rail while `--rail: 15rem` is 480px, leaving about 560px for content. Usable, not broken (reasoned from the spec, not run). The 320px/200% e2e passes but a wide viewport at 200% is not exercised, which was a stated review focus. Fix: add an e2e at 1100px/200%, or choose the layout without a rem breakpoint.

5. **Text over the backdrop is not contrast-verified** - `apps/desktop/src/theme/base.css:4-5`, `apps/desktop/src/theme/Backdrop.tsx`.
   Body has no background, so text outside panels (headings, nav titles in bar mode, ghost buttons) sits directly on the SVG. The scrim is transparent at the right edge where the indigo glow and gilded windows are brightest; `--text-muted` over the glow centre is about 4.4:1 (estimate). The handoff admits this is judged by screenshots only. Fix: put `.app-content` on a translucent `--surface` panel, or raise the scrim opacity toward the right.

6. **HelpTip viewport clamp is untested** - `apps/desktop/src/ui/HelpTip.tsx:35-48`, `apps/desktop/src/ui/ui.test.tsx`.
   The clamp was a stated review focus, but jsdom reports width 0 so the code returns early and no test reaches it. The layout effect depends only on `[open]`, so a resize or content change while open leaves a stale shift. Fix: mock `getBoundingClientRect` and `clientWidth` in one test; re-measure on resize.

7. **Nav group ids come from the title's first letter** - `apps/desktop/src/App.tsx` (`nav-group-${title.charAt(0)}`).
   Works today (P, D) but collides when two groups share an initial. Fix: use a constant per group or `useId`.

8. **Contrast declarations cover tokens, not real compositions** - `apps/desktop/src/theme/contrast.test.ts`, `tokens.css:8-41`.
   Findings 1 and 3 slipped through because gradient stops and `::selection` are not declared. `--text-muted on --mist` is 4.31:1 and undeclared (no current use found). Fix: add a pair per gradient stop and per background/colour combination in base.css and ui.css.

9. **Packaging check covers the notices, not the font binaries** - `.github/workflows/package-windows.yml`.
   The new step byte-compares OFL-Inter.txt, OFL-Cinzel.txt and THIRD_PARTY.md, which is what ADR 0005 decision 4 asks for. Nothing in CI verifies the font files against the hashes in THIRD_PARTY.md. Fix: a unit test that hashes `src/theme/fonts/*` against the table in THIRD_PARTY.md.

10. **Handoff wording** - `docs/handoffs/2026-10-17-g4.md`.
    "Both fetched and verified" is not reproducible from the repo (nothing re-fetches upstream). It is an honest record, not CI evidence. The handoff correctly marks WebView2, the native white-flash fix and the NSIS layout as unverified.

## Verified as correct (no finding)

- Fonts unmodified in the repo: `sha256sum` of the four files in `apps/desktop/src/theme/fonts/` matches THIRD_PARTY.md exactly (Inter 693b77d4..., Cinzel f4d83d34..., OFL-Inter 262481e8..., OFL-Cinzel f2b3029a...). Plain git blobs, no LFS. `git check-attr`: `text: unset` for the fonts, `text eol=lf` for THIRD_PARTY.md, so checkout is byte-exact. The tauri.windows.conf.json resource paths resolve relative to `src-tauri`.
- OFL notices carry the upstream copyright lines; no subsetting, conversion or renaming (Cinzel stays TTF).
- CSP: `fonts.css` uses relative `url()` bundled by Vite with `assetsInlineLimit: 0`; `check-dist` is clean; the new prod-csp test confirms both faces load with no violation. No `data:` or remote URL in `src`. Inline `style` use (HelpTip transform, ember delays) falls under the existing `style-src 'unsafe-inline'`.
- Backdrop is original code-generated inline SVG. No jpg, no `dragon-citadel`, no raster, no Blizzard art or client fonts (ADR 0005 decision 5). It is `aria-hidden`, `pointer-events: none`, hidden in high contrast and forced colours, and embers stop under `data-motion=reduced` and `prefers-reduced-motion`.
- Rust: `.background_color(tauri::window::Color(0x16,0x18,0x26,0xff))` - `WebviewWindowBuilder::background_color(Color)` exists in tauri 2.12.3 and `tauri::window::Color` re-exports the tuple struct `Color(u8,u8,u8,u8)`. Not compiled here.
- Global CSS: element rules use `:where()` so screen CSS still wins; removing `main { max-width: 48rem }` widens screens to 72rem (intended). settings.css high-contrast rules still apply.
- Nav: one `nav[aria-label=Primary]`, 14 buttons with unchanged names, `aria-current="page"`, two labelled `role=group` groups, heading outline unchanged; e2e `SCREENS` order matches `App.tsx`.
- Tests are not vacuous: the contrast test parses tokens.css and recomputes WCAG ratios; ui tests assert roles, names, aria state and bubble removal. The weakness is coverage (findings 6, 8), not tautology.
- Handoff claims match the code and the counts I reproduced (14 buttons, h1 text, Settings non-affiliation line, backgroundColor in both places, hashes, 329 unit tests, 158 e2e passed / 1 skipped).

## Resolution (2026-10-17)

Important 1: the primary gradient now runs `--ember` to `--ember-shade`; a
`--on-ember on --ember-shade` pair is declared and tested. Important 2: the bubble is
always mounted (hidden while closed) so `aria-describedby` resolves on focus, has
`role="tooltip"`, and a document-level Escape listener closes it (new unit test for
hover-only opening). Important 3: `::selection` uses `--select-bg/--select-fg`
(white on black in high contrast, Highlight/HighlightText in forced colours) with a
declared pair. Optional 4-10 are not changed in G4; they are carried to G5 / the
0.9.2 TODO. Rechecked: typecheck, lint, 336 unit tests, build, check-dist, Playwright
158 passed / 1 skipped. Screen-reader announcement remains unverified.
