# Implementation review: M1.3 exchange contracts

Implementer: Claude Code (Opus 5.5), single writer
Reviewers: read-only Claude Code review workflow (4 review agents and 4 adversarial
verifiers, run inside the implementing session; not independent approval)
Date: 2026-10-12
Base: bc386c2 · Reviewed head: 1dc5c0d · Fixes: 827be4b

## Method
Four review dimensions ran against `git diff bc386c2...HEAD`: semantic
validation, Rust/schema/TypeScript fidelity, decoding boundedness, and tests/CI
reproducibility. Each finding went to a verifier instructed to refute it by
reproduction. Only findings the verifiers confirmed were acted on.

## Confirmed and fixed in 827be4b

- Medium: the fixture flag was compared only with envelope provenance, so nested
  `synthetic_fixture` observations could appear in a non-fixture document. Nested
  observation sources are now checked in both directions.
- Medium: the identifier schema pattern used JavaScript `\s`, which matches
  U+FEFF, so the schema rejected identifiers Rust accepts. It now uses
  `\p{White_Space}`; a valid fixture locks the parity.
- Medium: extension keys could shadow envelope members. They are now rejected.
- Medium: extension values were unbounded, and `serde(flatten)` buffered the
  whole envelope (about 460 MB peak for a 14 MB dataset with one large
  extension). The envelope is now deserialized by hand, and unknown members are
  size-checked as raw text before parsing.
- Low: extensions kept unsafe or lossy numbers. Numbers are now bounded to the
  safe magnitude.
- Low: a plan step alternative could repeat the step's own objective. Rejected.
- Low: the step-evidence check was cubic. It now uses a set.
- Low: the non-standard `int16` schema format stopped default Ajv from loading
  the schema. Such formats are stripped, and the test-only workaround is gone.

## Considered, not changed

- Party identity on plans: party membership is the set of input participants
  (documented). A party ID can be added with M7 party planning.
- Schema looseness for cross-field rules, extension limits and the session
  dependency is intended and documented in `schemas/v1/README.md`.
- Manifest checks compare error codes only. Every negative fixture differs from
  its valid base by one mutation, and each rejection reason was confirmed
  during implementation. Per-rule expectations are optional future hardening.
