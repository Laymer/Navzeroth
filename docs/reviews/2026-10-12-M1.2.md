## Findings resolved

- Domain validation initially checked nested build/namespace compatibility only
  when predicates ran. e408848 checks embedded requirements at record construction
  and deserialization, including branches execution could short-circuit. A mixed
  namespace acquisition requirement is rejected by its regression test.
- Full-width integer and duplicate-map decoding can silently lose information.
  Currency/source IDs use string encoding, numeric magnitudes are checked, and
  RecordMap rejects duplicate keys/over-limit collections. Regression tests cover
  values beyond JavaScript precision and duplicate conflicting preferences.
- Unbounded boundary input and raw parse errors could defeat otherwise checked
  types. e408848 supplies a 1 MiB domain JSON decoder, declared-schema checks,
  recursion/tree limits and safe application errors. Future transports still need
  bounded reads before building the input string.
- Initial CI failed Windows global Corepack installation due to the runner's Yarn
  shim. 8d3af68 isolated Corepack and passed on both OSes; this remains the verified
  bootstrap used for domain CI.

## Limits and next review

No unresolved blocker found for the agreed pure-domain scope. Tests are synthetic;
no game data or client behavior is verified. Domain structs are not final addon
exchange envelopes. Source/evidence IDs need dataset-wide resolution later;
capability categories alone do not establish source truth. Preference selectors
are boolean and generic numeric comparison selects level in this version.

M1.3 must finalize transport envelopes and schemas, preserve these invariants in
TypeScript/Lua representations, and add contract drift checks. In particular,
review observation metadata defaults, conditional value presence, safe integer
encoding, declared fixture/namespace correspondence and validated draft separation.
