# Review: M6.5 early atlas imagery slice

Revision reviewed: 57519d5 (feature/M6.5-atlas-imagery, five commits over
0c90c25). Method: a read-only adversarial workflow with four reviewers (plan
and AGENTS.md compliance, core correctness, CLI and content, test adequacy),
each in its own git worktree, followed by one independent verifier per
finding. 23 findings were raised; 19 were confirmed and 4 refuted. Fixes were
applied in the commit that follows 57519d5.

## Confirmed and fixed
- Missing handoff and review record (three findings): this record and
  `docs/handoffs/2026-10-12-M6.5-atlas-imagery.md` were added.
- Rights record named the pre-rename capitalized file name (three findings):
  corrected to the committed lowercase path.
- Content JSON had no `eol=lf` attribute, so a CRLF checkout on the Windows
  runner would change the manifest digest that `--check-pointer` compares:
  `content/**/*.json` and `content/**/NOTICE` are now LF, and `read_manifest`
  refuses a manifest containing CR with a diagnosable message.
- `DifferentFloor` detail was lost when the position's map had an embedding
  that led nowhere: the origin floors are kept and reported.
- Negative control-point residuals passed validation: now rejected (fixture
  `dataset-map-image-residual-negative.json`).
- Embedding cycle detection depended on record order (a chain leading into a
  cycle was reported as "too deep"): a visited set now reports any repeated
  key as a cycle (fixture `dataset-embedding-chain-into-cycle.json`).
- Depth boundary and runtime guard untested: tests cover a chain of exactly 4
  (projects, `via` length 4) and a deeper chain reaching the guard.
- Field-level doc comments on `$ref` members produced a duplicate
  `PixelPoint1` TypeScript type: docs moved to the struct level; regenerated.
- A layer output equal to the source, the manifest or the generated record
  would overwrite it: rejected in `read_manifest`.
- `--output` compared unnormalized paths: both are made absolute lexically.
- Committed demo layers and generated record had no drift test: added an
  end-to-end comparison; the forever dataset's claims (31 flight-layer pins,
  four tower routes, three shared masters, inferred provisional calibration,
  unrecorded third-party licences, no nodes or edges) are now asserted.
- `check.mts` did not assert the imagery summary: added.
- Stale generated record and layer-pointer mismatch in check mode were
  untested: added.

## Refuted (recorded for transparency)
- "`limited_sample` overstates third-party renders": the confidence names the
  evidence class; licences remain unknown and the notes say what was observed.
- "STATUS header omits the claim": the claim, owner and base are recorded.
- "Cross-build positions never reach the embedding fallback": by design;
  embeddings require exact context (ADR 0002) and the gap names the builds.
- "Windows runner smudges LFS despite `lfs: false`": actions/checkout sets
  `GIT_LFS_SKIP_SMUDGE=1` for its own commands; the pointer step would catch a
  materialized file anyway.
