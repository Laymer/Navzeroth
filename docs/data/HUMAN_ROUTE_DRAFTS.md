# Human 1–20 route design drafts

These are original review designs, not playable routes. The six classes are the
current authored vocabulary, not a verified launch eligibility list. Zone names
come from the requested slice. Every design leaves its quest sequence unknown,
eligibility unverified and actionable advice disabled.

Proposed review order: Northshire candidates, Elwynn candidates, Westfall
candidates, Redridge candidates, optional Deadmines preparation. This is an
ordering proposal without coordinates, level thresholds, travel edges or claims
that every character should visit each checkpoint. At each checkpoint, require
verified quest prerequisites/eligibility, objectives, rewards/XP, current character
state, travel/calibration and training/proficiency before choosing actual steps.

| Class | Solo design review | Duo design review |
| --- | --- | --- |
| Warrior | Compare the authored melee and tank models; leave training, equipment/proficiency and class detours pending facts. | Review each participant's declared role against the authored models; check individual progress and shared credit before proposing joint steps. |
| Paladin | Compare the authored melee and healer models; do not infer learned abilities or eligibility from a role label. | Review the chosen role with the partner's own snapshot, resources and progression; keep role swaps an explicit choice. |
| Rogue | Review the authored melee model, then require observed equipment/ability and quest facts for any class detour. | Retain each participant's separate quest log and objective state; do not infer shared completion from one capture. |
| Priest | Compare the authored healer and ranged models; leave training and item advice unverified. | Require both participants' current contexts and declared roles; evaluate minimum advancement for each before joint recommendations. |
| Mage | Review the authored ranged model; require verified training, resource and travel inputs before choosing steps. | Check both participants' eligibility and progress; do not assume a class label supplies transport or abilities. |
| Warlock | Review the authored ranged model; require verified ability, item and class-specific quest facts. | Keep the partner's progression and access separate; any class-specific detour remains pending evidence for both participants. |

Each solo design has a corresponding duo draft. Duo drafts additionally require
each participant's progress, shared-objective semantics and minimum-participant
advancement evidence. Partner class, actual abilities, quest choices and numerical
weights are not invented. Existing authored model weights remain labelled as
documented assumptions and are not promoted to verified client amounts.

The runtime design IDs and exact model references are in
`local_data_inventory::human_route_designs`. A verified authored-pack join reports
only that those model records exist. It cannot verify the route or its game facts.
A newly verified launch class requires its own models/design and explicit review.
