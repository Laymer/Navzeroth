## Delivered behavior
`SnapshotApplication` serializes SQLite access behind a mutex. Tauri commands
run normalization and all store queries on blocking workers; startup opens the
application-data SQLite database on a separate initialization worker. The
browser adapter remains explicitly synthetic and refuses imports/watching.

Explicit application DTOs cover text/file import, watch start/stop/status,
profile selection, profiles, current snapshot and bounded history. Profile IDs
hash an unambiguous serialized tuple of character, full DataContext and fixture
flag and resolve against stored complete keys; character-only IDs are refused.
Only character snapshot imports are accepted because the existing storage API
stores characters, not party envelopes. Snapshot transactions, hashes and
ordering are unchanged. Stored/duplicate/history-only outcomes retain all three
history reasons, fixture, namespace and capture freshness. Invalid input records
a bounded static audit error without replacing current state.

Manual imports select the imported profile. Watch imports preserve a different
user-selected profile; they select the first profile when none exists. Watch
start/stop operations are serialized, use generation guards, and stop/join the
previous worker before replacement. Polling uses R2 on its own blocking thread.
Watch receipt freshness is recomputed at receipt time, avoiding a start-time
clock frozen for the entire watch lifecycle. No addon layout is presumed: the
SavedVariables global/key are user inputs. Diagnostic probe exports are not
accepted as character snapshots.

Imports navigation supports pasted text and an explicitly entered path, format,
optional SavedVariables global/key, watch controls and recoverable error display.
Profiles show edition/build/interface/namespace and synthetic status. Current
and recent history snapshots show age uncertainty and preserve observation
states. Today displays stored capture age and synthetic labels. App polls watch
status to refresh Today/Atlas after a successful receipt; atlas markers use the
selected stored snapshot and its opaque application profile ID. Atlas reference
geography remains the existing labeled demo dataset, with projection gaps for
unsupported contexts; it is not a claim of installed real atlas coverage.
