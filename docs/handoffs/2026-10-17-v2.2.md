# V2.2: local extraction projections (first slice)

Owner and sole writer: Claude Code subagent (Opus 5.5); claim [2026-10-17-v2.2](../claims/2026-10-17-v2.2.md).
Baseline main `1840255`. Branch `feat/V2.2-local-projections`.

## Changed

- `crates/core/src/local_data_projection.rs` (new): typed, research-only
  projection records without I/O. `Fact<T>` is `known` / `unknown` / `missing` /
  `unsupported`, so zero (`known` 0) stays distinct and nothing defaults. Records:
  equipment items, maps, UI maps, UI map assignments (raw coordinate frames), taxi
  nodes, directed taxi paths with ordered waypoints, classes and races. Includes
  `SourceBinding`s, `LocalProjection::validate` (versions, no activation/planning
  flag, digest/locale shape, capacity, canonical order, unique waypoints), a
  summary type, and the authored inventory-type to candidate-slot mapping
  (`navzeroth-inventory-type-v1`; 0 means not equippable, unmapped values are
  unsupported).
- `crates/local-data/src/projection.rs` (new): `project` is the pure mapping over
  decoded tables for one declared locale. Each source is pinned to the single
  WoWDBDefs layout listed for 70374/70425 (ItemSparse `6fcc3191`, Item `9a2a4834`,
  Map `d43afac3`, UiMap `db51d55f`, UiMapAssignment `c9cc8dfb`, TaxiNodes
  `e7b597f0`, TaxiPath `a303de51`, TaxiPathNode `fe362e70`, ChrClasses `afc9b0c2`,
  ChrRaces `4f44c796`). Absent, undecoded, encrypted or other-layout tables are
  source gaps carrying the catalog disposition and reason; decoder gaps (encrypted
  sections) are gaps and mark the domain incomplete. Join and reference problems are
  counted gaps. Rows are sorted by identity, so bytes don't depend on stored order;
  duplicate identities refuse. Budget 1,000,000 records (waypoints included).
  `project_catalog` refuses unless the catalog is already in the store, takes the
  writer lock, verifies the catalog, hash-checks each decoded object and seals
  `projections/<sha256>`. `verify_projection` checks the hash, canonical encoding,
  invariants, the catalog closure and every bound decoded object, and re-projects
  for a byte comparison when the projector profile is the current one.
- `crates/local-data/src/extraction.rs`: the store accepts and creates
  `projections/`; `Store` is crate-visible for sealing.
- `crates/cli/src/local_data.rs`: `local-data project --destination --catalog
  --locale` (exit 3, research-only like extraction) and `local-data
  projection-verify --destination --projection` (exit 0). All options required;
  errors are path-free JSON.
- `docs/data/LOCAL_EXTRACTION.md`: projection section, store layout, remaining work.

## Not verified

- No projection was run against the owner's real 70425 catalog in this session
  (that catalog is in private storage outside this worktree). Whether the real
  ItemSparse (a sparse table) and the other tables decode in the research reader is
  whatever the catalog inventory says; undecoded ones show up as source gaps.
- The field semantics (for example `Region[6]` as minimum then maximum, the
  `StatPercentEditor` meaning, relation fields) follow WoWDBDefs names and are not
  checked in the client. They are labelled as standing gaps.
- Desktop (excluded from the checks, out of scope) was not built; only crate
  visibility changed in code it depends on.
- Adding `projection.rs` changes the extractor profile hash (it hashes every
  `src/*.rs`), so new extractions produce a different catalog digest than the
  earlier `bb906db2…` research run. That is expected for any code change.

## Limitations and next steps

- One projection per build and locale; other installed locales are projected by
  running `project` per locale. No cross-locale merge.
- Not done: activation and rollback, cache/hotfix import, consumers (planner,
  gear, routes, desktop), stat amounts (need item-budget tables), proficiency and
  dual-wield rules for slots, spells/talents for class roles, map/area hierarchy
  beyond the raw identities, travel unlocks/waits, and the hybrid
  `tested-content digest` binding to a projection digest.
- Suggested next: run `project` on the private 70425 catalog and record the source
  dispositions and counts (development evidence only, never relabelled as the
  target build); then decide the activation/rollback contract and bind the
  projection digest into hybrid delivery.
