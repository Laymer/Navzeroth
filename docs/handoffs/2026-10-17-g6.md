## Implemented

1. **HelpTip `label`** (G4 #8 / G5a #8). `HelpTip label="X"` names the trigger "Help: X"; without a label
   the name is exactly "Help". `Field` passes its label. Tests: `src/ui/followups.test.tsx`.
   Consequence for selectors: Playwright `getByLabel("X")` is a substring match and also matches the
   `aria-label` "Help: X", so the string-literal `getByLabel` calls in `e2e/` now pass `{ exact: true }`
   (stricter, not weaker). Three labels that wrap a control (the label text includes the control's
   own text, so an exact match cannot work) stay as they were: "I declare this whole session",
   "Requested reference interaction", "Recipient plan text", "Plan export text". The Settings Tab-order
   assertion uses `/^Help/`.
2. **Button `ref` and `aria-pressed`** (G5a #9, #10). React 19 passes `ref` as a prop, so `Button` types
   it (no `forwardRef`). The two native `ui-button` buttons in `AtlasScreen.tsx` (pin buttons) and
   `RouteInspection.tsx` (hop buttons) are now `Button`. A pressed `Button` gets a gold edge bar,
   bold and an underline (not colour alone). The legacy padding override in `styles.css` is scoped with
   `:not(.ui-button)`.
3. **Nested Panel** (G5a #11). A `Panel` inside a `Panel` (context) is `ui-panel--nested`: flat, a top
   rule, no frame, shadow or ornaments, zero horizontal padding (also in high contrast and forced
   colours). A top-level Panel inside a play screen uses `--space-3` side padding instead of
   `--space-4`. New `e2e/nested-panel-reflow.spec.ts` at 320 px and 200% text: Compatibility, Content
   (both have nested panels), Atlas, Gear, Planner, Sessions, Dungeons, and Party with two participants
   (joint planning, mocked as in `joint.spec.ts`). It asserts no horizontal overflow and, for every
   nested panel found, zero side padding and no shadow.
4. G4 optional items:
   - #4 rail/bar breakpoint: `.app-shell` is now a size container and the rail switch is
     `@container (min-width: 58em)` on a new `.app-body` wrapper. `em` in a container query resolves
     against the container's font size, so the Settings text scale is honoured (a `rem` media query is
     fixed at 16 px). E2E: a 1100 px window shows the rail at 16 px root text and the bar at 32 px
     (`navigation-reflow.spec.ts`). The rail now appears at about 928 px of shell content width at
     100% text instead of a 960 px viewport.
   - #5 text over the backdrop: `.app-shell` has a 90% `--surface` sheet (opaque `--surface` in high
     contrast, `Canvas` in forced colours). `composite.test.ts` composites that sheet over every colour
     in `Backdrop.tsx` taken fully opaque (a conservative bound) and requires 4.5:1 for text, muted,
     accent, gold and the four tones. Verified that lowering the sheet to 70% fails the test.
   - #6 HelpTip clamp: pure `clampShift`, re-measure on `resize` while open, listener removed on close;
     tests mock `getBoundingClientRect`/`clientWidth` (right overflow, left overflow, grow, shrink).
   - #7 nav group ids: `useId` plus `navSlug(title)`; tests for same-initial titles and two shells.
   - #8 composite contrast: every point (11 samples) of the primary, danger and secondary button
     gradients in default and high contrast; `::selection` must use `--select-bg/--select-fg`; a check
     that `--text-muted` is never set on a `--mist` background (the pair is 4.31:1 so it is
     deliberately undeclared; noted in `tokens.css`). The helper was split into `contrastLib.ts`.
   - #9 `fonts.test.ts` hashes every file in `src/theme/fonts/` against the table in `THIRD_PARTY.md`.
5. `docs/STATUS.md` current section updated.
