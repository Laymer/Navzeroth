## Decisions
No numbered ADR (ADR 0003 forbids packages from creating one). Design choices:
- Grammar: `ws* "ANAV1:" document ws*`, `ws` = SP HT LF CR; prefix case
  sensitive; UTF-8, byte order mark rejected; no whitespace between prefix and
  JSON; one encoding (compact canonical JSON), no base64 or compression. Whitespace
  padding is tolerated because clipboards and editors add it.
- The 4 MiB ceiling and JSON depth 32 are enforced by ingest before `decode_any`
  for every kind, so a 16 MiB reference dataset cannot enter through text. Default
  options accept character and party snapshots only; the kind is peeked and the
  policy applied before the payload is decoded.
- One validation funnel (`normalize`). Text, file and SavedVariables inputs produce
  equal `ImportResult`s; `ImportResult` therefore carries no "source" field.
- No `transport_digest` and no identity hash: P1 owns identity (sha2 over the
  canonical validated envelope). Nothing in ingest computes a hash.
- Freshness uses `observation::freshness` with a caller-supplied
  `FreshnessContext`; with no trusted clock it is `Uncertain`. Nothing is labelled
  live. `ImportResult::is_fixture_or_demo()` lets production callers refuse
  synthetic/demo data (CASE-015, import half).
- SavedVariables subset (documented in the module and README): `nil` is rejected;
  `--` line comments are accepted (real files carry `-- [1]` markers), long
  comments and long strings are rejected; numbers are `-?digits(.digits)?(e[+-]?digits)?`;
  bare identifiers are only accepted as keys, `true`, `false`. Positional values
  take keys from 1 and collisions with explicit keys are duplicate-key errors.
  A string that decodes to non UTF-8 is rejected, never converted lossily.
- The parser recurses, but table depth (32) is checked before each recursion, so
  the stack is bounded even on Windows' 1 MiB main stack. A 200,000-deep input is
  tested.
- `extract_export(file, global, key)` takes both names as parameters; only tests
  and the fixture manifest (`saved_variables.global/key`) name `AzerothNavigatorDB`
  and `export`. This layout is an UNVERIFIED engineering assumption pending M0.5.
- `validate-fixtures` resolves the repository root from `AZEROTH_REPO_ROOT` if set
  (tests, relocated binaries), otherwise from `CARGO_MANIFEST_DIR/../..` at compile
  time, so it works from any working directory. The two fixture directories are an
  explicit list; no glob. Output is a count per manifest; failures print the
  manifest label, a validated plain file name and a fixed reason, never content.
- `.gitattributes` untouched: `fixtures/**` is already `eol=lf`; CRLF variants are
  built in memory.
- Pure redaction helper for bounded error excerpts (plan 16.2) not added: errors
  carry static messages only, so no excerpt exists to redact. Recorded as a
  follow-up if a diagnostics surface needs excerpts.

## Limitations
- The SavedVariables serialization and the global/key layout are UNVERIFIED until
  M0.5 on a live Forever client; the accepted subset may need widening (escape
  style, number formats, comments, line endings, `nil` handling).
- The dedicated `validate-fixtures` CI step is NOT added (ci.yml is owned by P11;
  ADR 0003 defers it). Coverage today is `cargo test` (`crates/cli/tests/validate_fixtures.rs`
  and `crates/ingest/tests/fixtures.rs`), which the required Rust jobs run. M1.5 is
  therefore partly delivered. The README line about `validate-fixtures` being
  planned is also left for the integration docs PR (README.md is frozen).
- No watcher, debounce, storage, identity hash, ordering of old/new snapshots, or
  Tauri command. The addon encoder (M2.1) must follow the grammar in
  `schemas/v1/README.md`; reconcile `AzerothNavigatorDB` keys with P11's
  `docs/compatibility/ADDON_SAVEDVARIABLES.md` in wave 2.
- `import_file` refuses symlinks and non-regular files with `symlink_metadata`
  then bounded read; a path swapped between those two steps is not defended.
- Error messages are static, so diagnostics carry no position information; only
  the closed `Rejection`/`Problem` codes.
- No Lua parity, no property-testing crate (bounded deterministic loops instead,
  per the prompt).

- Review record: the adversarial review of this package found nothing to fix. PR
  20 had already been merged into main (at 3e8c8eb) when the review record was
  written, so the record and this handoff update reach main only through a
  follow-up PR.
