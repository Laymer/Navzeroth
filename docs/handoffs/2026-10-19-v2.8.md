# V2.8: world-data automation

Owner and integrator: Claude Code (Opus 5.5 / Sonnet 5.5), claim
[2026-10-19-v2.8](../claims/2026-10-19-v2.8.md). Decisions:
[ADR 0007](../decisions/0007-world-data-automation.md). Baseline: `origin/main` after
the V2.7 merge (PR #208). Branch `feat/V2.8-world-data-automation`, built in an
isolated worktree; seven sub-tasks ran as worktree-isolated subagents and were
merged by the integrator. Codex's checkout was not touched.

## What landed

- **Pipeline.** `python3 data-generators/pipeline.py`: detect, generate, verify,
  register, content, gate, publish. Detect reads the installed client's
  `.build.info` (`--client`, probes of the usual Windows install paths under WSL, or the
  git-ignored `data-generators/local.json`) and writes
  `release/v1/world-data-target.json` (now `wow_forever` 1.60.1.70450, interface
  16001). Publish commits through a private git index to a `data/` branch, never
  pushes `main`, never force-pushes, and opens a draft PR.
  `.github/workflows/world-data.yml` runs it weekly without Wowhead.
- **Research catalog.** `register_facts.py` registers every generated fact
  (2.86 million) as admitted source files; limits raised (`MAX_FACTS` 6,000,000,
  catalog 8 GiB, closure 2 GiB) and the build streams its catalog (peak 4 GB
  instead of 14 GB). Retained fact objects are in Git LFS and the source-knowledge
  workflow pulls them.
- **World content pack.** `world_to_content.py` writes `content/world/1.60.1.70450/`
  (content v2, LFS): about 24k items, 58k acquisitions, 4,245 quests, 8,800 nodes,
  32k edges (315 flight, rest inferred walk), 21k NPC/object entities and 8,104
  loot tables, with a conflict report. Contract additions (all optional, existing
  packs keep their bytes): `entities`, `loot_tables`, `EquipmentFacts.name`,
  `QuestFacts.title/givers/enders`, `Dungeon.bosses`, slotless non-equippable items.
  Pack limits raised (identities 500,000, catalog 576 MiB). Documented in
  [WORLD_CONTENT.md](../data/WORLD_CONTENT.md).
- **Gate.** Accepted-origin policy (`release/v1/accepted-origins.json`,
  `origin_policy.rs`), accepted unknowns, release schema 3 (target from
  `world-data-target.json`, no LIVE-* or slice matrix, policy file hashed into
  evidence), `MAX_RECORDS` 2,000,000. A pack source lists `[true origin, target]`
  editions; evidence that claims a strong confidence from a non-target origin is a
  relabel and blocks. Readiness blockers on the integration branch: **52**
  (69 before): the WIN-* observations, inventory, coverage, the initial tested
  binding and packs not yet bound to a release candidate.
- **Application.** Origin marker ("From 1.12 data" / "From Classic Era data" /
  "Inferred") on gear, planner, routes, dungeons and the new World browser
  (NPCs/objects, vendors, trainers, quests, loot; server-side search and pages).
  `activate_content_set` activates the authored and world packs as one set, with an
  "accept inferred travel" choice. Route search works on the whole world graph
  (bounds 32,768 nodes / 131,072 edges; prepare 52 ms, queries 0.5 to 30 ms on the
  real pack); flight edges with unknown requirements are usable as estimates and
  always flagged as assumed.

## Independent review

A worktree-isolated review agent reviewed the integrated head. Fixed: a blocker (the
pack's derived `navzeroth-world-content` source had no editions, so the schema 3 gate
would refuse it; it now lists the target edition and the pack was regenerated and
re-verified), publishing did not stage `.gitattributes` (new LFS rules would not
reach the PR), the weekly workflow pulled the full LFS set every run (now no LFS
download), the world browser's copy implied unmarked facts are Forever, and stale
statements about `MAX_RECORDS`, the 70374 target and the superseded edition rule.
Recorded as known limits in [WORLD_CONTENT.md](../data/WORLD_CONTENT.md): route search
memory on unreachable targets, desktop peak memory and the quadratic merge when
activating the world pack, unresolved quest giver/ender and loot source references,
the target-build stamp on wago evidence, and that the weekly draft PR gets no CI
checks with the default token. **The world pack has not been put through the release
gate as a listed pack**: the committed readiness report lists no packs; binding it
needs release evidence and coverage rows (task V2.5).

## Not verified / limitations

- The `azeroth-desktop` crate does not build in this WSL environment (`libdbus-sys`),
  so the `activate_content_set` Tauri wiring and its native boundary tests are
  unverified locally; CI covers them. Nothing was run on Windows or against a live
  client.
- The weekly workflow, the publish stage against GitHub and the repository setting
  "Allow GitHub Actions to create and approve pull requests" are unexercised.
- The source-knowledge workflow now pulls about 620 MB of LFS objects per run and
  uploads multi-GB artifacts; run time, memory and quota on hosted runners are
  untested.
- The inferred-travel choice is in memory only; a restart returns to the strict
  default until it is set again.
- World data limits: the pack decodes at about 14 times its size (4 to 5 GiB peak);
  the desktop pays this on load. Flight requirements are assumed, not checked;
  trainer spells have no content type; the world pack has no `objectives` records
  (stages are on the quests); 20 of 27 dungeon entrances (including the Deadmines)
  are unknown; disenchant loot sources stay unknown by design.
- Professions and enhancements still need the Wowhead pages the owner saves
  (`import_wowhead_pages.py`). Fishing is in the world data only for the datasets that
  exist.
- Dropping the LIVE-* checks and the build freeze means 1.0.0 can ship without
  live-client evidence (ADR 0007); the origin marker and conflict report are the
  visible guard against wrong-for-Forever facts.
