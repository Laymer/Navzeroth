## Implemented

- **Spike result (which attach works).** WebView2 CDP + Playwright `connectOverCDP` works.
  The plan's launch method does **not**: `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` is ignored
  by this app on the hosted runner (Tauri passes its own browser arguments through the API;
  none of five env-var variants opened a port, runs `38947474357` and `38949898107`). The
  documented WebView2 machine policy `HKLM\SOFTWARE\Policies\Microsoft\Edge\WebView2\AdditionalBrowserArguments`
  (value name `azeroth-desktop.exe`, data `--remote-debugging-port=N --remote-allow-origins=*`)
  **is** honoured (HKCU is not). `Native-Smoke.mjs` writes it before launching and deletes it in
  `finally`. It changes only the ephemeral runner. The WebDriver fallback (tauri-driver +
  msedgedriver) was therefore not needed and was not implemented.
- `Native-Smoke.mjs --mode smoke` on an empty database, after the silent install:
  actual CSP read from the response header; no `securitypolicyviolation`/console CSP
  messages; `__TAURI_INTERNALS__` present and no `DEMO —` label; exactly 14 navigation
  buttons; each of the 14 screens renders (alerts recorded verbatim, only
  `PROVIDER_UNAVAILABLE` fails); import of `fixtures/transport/anav1-character-snapshot.txt`;
  stage and activate the synthetic planning content; planner verdict; reference window
  state query; schema_migrations summary. Screenshots and a JSON report are uploaded as the
  artifact `native-smoke-evidence-<sha>` (never part of the release asset set).
- Upgrade smoke: `gh release download v0.9.1` (`*-x64-setup.exe`, `SHA256SUMS.txt`), digest
  verified against the checksum file (`--mode check-download`), install baseline, populate
  through CDP (`--mode populate`), record `schema_migrations` (`--mode db-summary`), install
  the candidate over it, `--mode verify` (profile, active content, Today survive), assert the
  migration version did not go backwards and no table disappeared, then a bounded downgrade
  attempt (only when the candidate is newer) that must leave the installed version unchanged.
- Pure helpers (args, CSP/alert classification, SHA256SUMS parse/verify, version
  comparison, upgrade classification, policy arguments, step recorder) are in
  `native-smoke-lib.mjs` with 9 `node --test` tests that run on Linux and in CI.

## Limitations

- Unverified: the **downgrade refusal** (`allowDowngrades:false`) and a true **migration across
  versions**. Both need baseline < candidate; first possible in G8 (0.9.2 vs 0.9.1).
- Unverified: native `inspect_plan_route` and `export_plan` (needs a snapshot with trusted age).
- Unverified: real file import and watch, native dialogs, reference-window show/hide, DPI,
  keyboard focus, visual fidelity, SmartScreen, anything on a live client (70374 or 70425).
- The hosted runner is one environment; a WebView2 runtime update can change behavior.
- The machine policy is an administrator-only runner change; it will not work in an
  unprivileged environment.
- The upgrade populate step runs the candidate's driver against the baseline UI, so the
  exact accessible names of the Imports and Content screens must be kept (G4/G5 rule).

## Review focus

- Whether skipping export on the trusted-age refusal is acceptable, or a fresh synthetic
  capture should be authored (that would need a deliberate, labelled fixture).
- The `Stop-NativeSmokeProcesses` WebView2 filter and `Uninstall-NativeSmokeApp` waits.
- The policy key is removed in `finally`; a hard runner crash would leave it, which is harmless
  on an ephemeral VM.
