## Delivered behavior

`export_plan` reruns bounded planning under the same application mutex that guards
snapshot and active content selection. It ignores frontend results. The pure
compiler emits v1 RoutePlan plus ANAV1 framing, with stable SHA-256 plan/step IDs
from sorted canonical request/context/fixture and implementation versions. Generation
time stays separate; expiry is min(snapshot capture + existing 30-minute freshness,
generation + 30 minutes). Existing build/dataset/snapshot/ruleset revalidation
triggers remain. Estimates, exclusions, selection explanations, filtered/decision
reasons, evidence, declared route conditions and explicit manual inputs are retained.
Only selected inbound legs and the final stopping route are concatenated.

Prerequisites combine selected route conditions and objective conditions. Accepted
quest-stage readiness uses declared stage membership and v1 quest/global-objective
predicates (global objective state must be available). Invalidation negates readiness;
it requests revalidation, never completion. Stateful travel readiness, acquisitions,
empty selections and more than eight per-step alternatives are refused with guidance.
No conditions or outputs are silently truncated. Limits: 32 KiB total ANAV1 text,
JSON depth 32, predicate depth 12, 8192 JSON value nodes, 1024 collection entries,
4096-byte strings plus existing contract identifier/text bounds and 32 selected steps.

Lua `importTransport` strictly validates ANAV1 framing and total text size, then
uses existing transactional raw-JSON `importText`; failed replacements retain the
loaded plan. Raw-JSON callers stay compatible. Export text is selectable and shows
bytes/expiry; clipboard writes happen only on the explicit Copy action. Input edits,
profile/catalog refresh and superseding requests invalidate pending/displayed exports.
