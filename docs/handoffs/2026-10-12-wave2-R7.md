## Delivered behavior and decisions
Migration 2 adds dataset_revisions, dataset_manifests, source_records,
source_conflicts and active_datasets. Immutable rows reject update/delete;
inserting the manifest seals source/conflict insertion. Full-context composite
foreign keys prevent active/previous pointers crossing edition, build,
interface, namespace or fixture status. The version-1 snapshot schema is intact.

`ContentRevision` contains the existing validated ReferenceDataset envelope,
source registry records and classified conflicts. Staging re-decodes the
bounded envelope, runs the existing coverage validator, requires registered
sources and honors known edition exclusions; missing/foreign conflict
references fail. Errors prevent staging, while coverage gaps remain recorded.
Sources and conflict lists are canonicalized; reuse of a revision key with
different envelope/policy/conflict content fails rather than overwriting it.
Manifests carry an internal version, SHA-256 and deterministic coverage report.
No snapshot hash algorithm or exchange schemas changed.

Activation revalidates stored content/hash/coverage and child records inside
an immediate transaction, then moves only its complete-context pointer.
Failed activation leaves the previous active revision untouched. Explicit
activation can choose any retained revision. Rollback revalidates the previous
revision and activates it; repeated rollback toggles between the last two.
The caller makes the activation choice; staging does not automatically activate.

Bounds: 1024 revisions, 1024 source/conflict records per revision, 1024 other
evidence IDs per conflict, 32 MiB combined revision serialization. The existing
16 MiB dataset envelope bound still applies. Nothing truncates silently.

`backup_to` uses SQLite's supported backup API and exclusively creates a new
destination. Existing files are preserved. Busy/locked backups return a
retryable StorageError, with no unbounded retry loop; incomplete newly-created
outputs are removed. Restoration is verified by reopening the backup through
the normal migrator/revalidated read APIs; no destructive restore-overwrite API
was added. WAL is not enabled by default, but committed WAL content is backed up.

## Limitations and next work
Library repository APIs only, not content installation UI/archive extraction,
authenticated distribution, or packaging. Conflict classifications are
preserved from normalization; storage checks references, not competing payload
semantics or undeclared original provenance. Reference entities remain in
immutable envelope documents rather than separate query tables. No API-derived
source is fetched and no redistribution permission is inferred from unknown
policy. Retention/deletion policy and revision pruning need a separate scoped
implementation before ingesting providers with such obligations.
Next dependency-ready work: explicit app/CLI content activation choice and
coverage display, then verified bundle/recorder integration. Native packaging,
backup under crash/fault injection and live client behavior remain unverified.
