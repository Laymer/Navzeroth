## Goal and scope
The pure core slice of M8.1/M8.3 under ADR 0003 (wave-1 package P7): a local
session event model, a builder that emits one `SessionSummary` per `SessionId`
rebased to t=0, gap and clock-change handling, bounded input, and an idempotent
summary merge. Out of scope: the addon recorder part of M8.1, M8.2 progression
summaries and M8.4 calibration (wave 2), storage, CLI, desktop. No wire or
contract kind was added. The input event shape is provisional until the
M2/M2.1 addon export exists.

## Decisions
- No ADR (ADR 0003 covers the early start). Design notes live here and in the
  module docs.
- Durations come only from same-session monotonic `elapsed_ms`. UTC never
  contributes to a duration; it is mapped to `start_utc_ms` only when the first
  event is Trusted and there are no clock flags or discontinuities.
- A session summary covers [0, elapsed_ms]. A decrease of the monotonic value
  while the sequence increases (reset) and the span after a logout event are
  zero-width gaps, so they add 0 ms and the timeline continues from the same
  position. `elapsed_ms` is therefore measured monotonic coverage, not
  wall-clock time. A session-start event after the first event with running
  monotonic time is a `reload` gap of its real width; a pause-to-resume span is
  a `recording_disabled` gap of its width.
- A span between consecutive events longer than `max_observed_span_ms` is an
  `Unclassified` interval; an `Observed` activity marker over the limit is
  demoted to `Unclassified`. An `Estimated` marker stays `Estimated`. Spans
  with no marker and within the limit are `Observed` with label `observed_span`.
  An Activity marker classifies the span that ends at it.
- Plan terms map to the entity without new variants: measured = Observed,
  inferred = Estimated, unclassified = Unclassified. Gap time is reported
  separately; the four totals never exceed `elapsed_ms`.
- Starting/ending level: the first/last Known observation, else the first/last
  level observation (keeping unknown/restricted/unsupported), else Unknown.
- Identical duplicates of a (session, sequence) are dropped; a different event
  under the same pair is `InvalidInput`. Events are ordered by sequence.
- Bounds: 1024 events per session before deduplication and 64 sessions per
  batch, both `ImportTooLarge`; nothing is truncated. Equipment from another
  data context gives `BuildMismatch`.
- Reasons `MissingData` and `ClockChange` from the task text were left out: no
  producer for them exists yet. Clock changes are reported as
  `SessionClockFlag`, not as gaps.
- merge_summary keys on (CharacterId, SessionId); an equal summary is Unchanged,
  a differing one is Conflict and never replaces. The caller owns the store.

## Limitations
- No review has been recorded yet (see Validation).
- Input shape is provisional and not a contract kind; the addon recorder (M8.1)
  and the SavedVariables layout do not exist yet.
- How GetTime/session time behave across /reload and logout, and whether a
  producer reuses a session ID after either, is UNVERIFIED (M0.3-M0.6). The
  producer session ID and the monotonic value are treated as opaque.
- Persistence of summaries and the P1 store are wave 2; merge works on an
  in-memory map.
- `elapsed_ms` of a session with resets or logouts is monotonic coverage, not
  wall-clock duration; consumers must not display it as elapsed real time.
- Sequence holes are not treated as missing data (the sequence contract is
  unverified).
- The fixtures are not covered by `pnpm contracts:check` or the P2
  validate-fixtures CLI; only the Rust manifest test loads them.

## Review focus
- Whether the zero-width gap convention for resets and logout is acceptable
  given that `SessionSummary` cannot hold more than one monotonic origin.
- The ordering by sequence, and treating an elapsed decrease as a reset even for
  out-of-order delivery.
- Interval merging (adjacent equal label and quality) and that it never crosses a gap.
- `UtcDisagrees` tolerance semantics and the choice to leave durations untouched.
