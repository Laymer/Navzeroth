## Goal and scope
The Atlas screen of ADR 0002 PR-B over the synthetic demo atlas only:
commands `query_atlas`, `project_positions`, `get_snapshot_markers`; the
`atlas` URI scheme restricted to dataset-declared, hash-verified layers; Today
and Atlas navigation; a hand-rolled pan/zoom viewport; the snapshot marker with
its capture age; a schematic fallback; accessible loading, empty, error and
stale states.

Out of scope and not done: `toggle_overlay`, `solve_calibration`, the overlay
window, search and filters, routes, Playwright/e2e (`test:e2e` stays planned),
tiling, loading the Forever dataset, and any new dependency except
`sha2 = "=0.10.9"` for azeroth-app (already in Cargo.lock through azeroth-cli).

## Implemented
- crates/app/src/atlas.rs (pure; no clock, filesystem or network):
  - `query_atlas(image)` / `query_atlas_with(image, SchemeStyle)`: revision,
    namespace, fixture flag, `data_mode: demo`, per image the layers (URL,
    availability, declared sha256), pins (each `reference_only: true`),
    calibration status and weakest-evidence confidence, an `approximate` display
    flag, gaps text and attribution. A layer that would be refused is never given
    a URL.
  - `project_positions(&[Position])`: 1..=64 positions, otherwise a static
    `INVALID_INPUT` that does not echo input. Results are
    `{outcome: "placed", ...Projection}` or `{outcome: "gap", gap: ...}` from
    core `project_position`; nothing is reimplemented.
  - `get_snapshot_markers(now_utc_ms)`: observed/received times, core
    `freshness()` with a 30 minute limit (trusted clock only when `now` is
    given), the projection or gap, `approximate`, `fixture`, `data_mode`. Only a
    known location is projected; unknown/unsupported/restricted/not-applicable
    produce no pixel. `snapshot_marker_for` takes an explicit snapshot for tests.
  - `resolve_atlas_asset(path)` / `resolve_asset_with(dataset, path, source)`:
    exact `<image id>/<layer id>`, percent-decoded once, ids restricted to
    `[A-Za-z0-9_-]`, exact match against dataset-declared ids, bytes from a fixed
    `include_bytes!` table keyed by the declared `AssetPath`, sha256 checked
    against the declared digest (cached once in a `OnceLock` for the embedded
    set; the injectable form hashes on every call). `serve_atlas(method, path)`
    adds GET-only and status mapping (404 for invalid/unknown/not embedded, 403
    for a digest mismatch, 405 for other methods, empty bodies on refusal).
  - `SchemeStyle::layer_url`: the one place URLs are built
    (`atlas://localhost/<image>/<layer>` on Linux/macOS,
    `http://atlas.localhost/<image>/<layer>` on Windows/Android).
- apps/desktop/src-tauri: `atlas_protocol.rs` (25 lines, adapts `serve_atlas`
  to `tauri::http::Response`, sets `Cache-Control: no-store` and
  `X-Content-Type-Options: nosniff`), explicit command wrappers registered in
  `generate_handler!` (`get_snapshot_markers` reads `SystemTime` once, here only),
  `register_uri_scheme_protocol("atlas", ...)`, and CSP
  `img-src 'self' atlas: http://atlas.localhost`. capabilities/default.json is
  unchanged (empty permissions).
- fixtures/desktop/atlas/*.json: golden DTO JSON written by a comparing Rust
  test (rewritten only with `UPDATE_DESKTOP_FIXTURES=1`): the atlas view, the
  position projection cases (placed, embedding fallback, namespace mismatch,
  different floor, build mismatch) and markers (fresh, stale, uncertain,
  restricted location, gap on another floor). The golden atlas view is written
  with the non-Windows scheme style so it is identical on every platform.
- apps/desktop: Today/Atlas `nav` with `aria-current`; `atlas/viewport.ts` (fit,
  zoom and pan clamps, zoom at a point, centre, screen/frame round trip, key
  map); `atlas/markerState.ts` (closed 20-key union with pairwise distinct
  labels); `atlas/layers.ts`; `atlas/describe.ts`; `atlas/MapView.tsx` (CSS
  transform for the raster layer, a screen-space SVG overlay for frame, grid,
  pins and marker, schematic fallback, drag, wheel, buttons, keys scoped to the
  focused region); `screens/AtlasScreen.tsx`; hand-written DTO types and
  `CommandMap` entries in `commands/contract.ts`; client wrappers; demo adapter
  answers from the golden JSON with bundled demo PNGs. Forced-colors CSS rule
  added. State is conveyed with words, shapes and dashes, not colour alone.

## Decisions
- No ADR was created (ADR 0003 forbids numbered ADRs from packages).
- Core is untouched. `confidence_rank` and the approximate rule are local to
  crates/app because core's equivalent is private; the `approximate` flag is a
  display rule (true unless `verified_on_build`, or `limited_sample` with at
  least three control points), not an evidence precedence.
- The browser demo adapter has no trusted clock, so it serves the "uncertain"
  golden marker (`age uncertain`) instead of recomputing freshness in TypeScript.
  It answers `project_positions` only for the golden sample list and refuses any
  other list with `INVALID_INPUT`; it has no projection engine by design.
- Layers are full images, so the topmost enabled one is drawn (flight, then
  roads, then overview/terrain); the screen says so.
- Layer availability is explicit (`available`, `not_embedded`,
  `integrity_mismatch`, `unservable_id`) so a refused layer is explained rather
  than silently blank.
- Edge handling stays inclusive as in core: the demo snapshot at y = 1.0 lands
  on pixel y = 96 of 96 and is placed.

## Limitations
- Demo dataset and demo snapshot only; wiring to stored data is M2.4.
- The demo calibration is identity and `inferred`, so every marker is labelled
  "approximate, uncalibrated"; the uncertainty ring has a fixed screen radius
  because no residual statistics exist yet.
- The attribution line is built from the source id and namespace; licence text
  is "not recorded in this view" because the demo evidence carries none.
- The browser demo shows "age uncertain" (no trusted clock); fresh/stale come
  only from the Tauri build or from tests.
- `project_positions` has no UI caller yet (search and routes are out of scope);
  it is covered by handler and golden tests.
- Layer images are decoded by the webview at full size; no tiling or overview
  level selection is implemented, which matters for the Eastern Kingdoms poster.
- Required CI jobs do not run the desktop scripts; they were run locally.

## Review focus
- Resolver: path parsing (single decode, safe-id alphabet, exact match) and that
  `serve_atlas` can never reach anything but embedded, hash-verified bytes.
- `SchemeStyle` URLs versus the CSP (`atlas:` and `http://atlas.localhost`) on
  Windows; the first launch is the real test.
- Golden files: regenerate with `UPDATE_DESKTOP_FIXTURES=1` and confirm the diff
  is intended; the TS shapes in `atlas/golden.shapes.ts` must follow.
- `approximate` rule and the marker-state wording ("Last imported", never
  "Live", "approximate, uncalibrated").
- Viewport clamping when the frame is smaller than the region (centred) and the
  inclusive frame edge.
