# V1.3: owner-held operator and reviewer keys

Owner and sole writer: Claude Code (Opus 5.5); claim [2026-10-17-v1.3](../claims/2026-10-17-v1.3.md).
Baseline main `5598733`. Branch `feat/V1.3-signer-rule`. No subagents wrote code.

## Changed

- `local_data_release.rs`: delivery policy format 2 allows one identity to hold at
  most one key per role (so one operator and one reviewer key); format 1 still
  requires distinct identities. Keys are always unique. Receipt payloads gain
  `independent_review_sha256`: required and a valid SHA-256 in format 2, forbidden
  in format 1 (skipped when absent, so format 1 canonical bytes are unchanged).
- `receipts.rs`: format 2 payloads sign under the domain tag
  `NAVZEROTH\0LOCAL-CATALOG-RECEIPT\0V2\0`. The receipt and payload versions must
  agree. A shared identity verifies only when the policy and the receipt are both
  format 2. Roles, keys, revocation, trust, bindings and the operator-then-reviewer
  order are checked as before.

## Checks (actual, WSL2)

- `cargo fmt --all --check`, clippy `-D warnings` (workspace minus desktop): pass.
- `cargo test --locked --workspace --exclude azeroth-desktop`: 1,108 passed, 0 failed,
  4 ignored. The receipt tests have three new cases: a shared owner accepted only
  with format 2 and a bound review; format 2 still refusing shared keys, duplicate
  roles and revoked signers; and format 1 receipts unable to reuse format 2
  signatures. The last one passes partly because the payload bytes differ anyway,
  so it doesn't isolate the domain tag by itself.

## Not done

- `config/release-delivery-v1.json` stays format 1 / `bundled_content` with no
  signers; V1.2 introduces the hybrid policy. No real key exists or was generated.
- Both the policy and payload targets are still 70374 (V4.2).
- What counts as an acceptable "independent review record" (format, who reviews)
  is a process rule for V5.4, not encoded here beyond the hash binding.
