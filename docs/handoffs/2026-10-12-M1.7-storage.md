## Goal and scope
New crate `azeroth-storage` (package P1 of the wave-1 delegation, ADR 0003 on
docs/wave1-coordination): a synchronous SQLite store for character snapshots,
profiles, profile preferences and an import audit trail, with versioned
migrations, content-hash idempotency and a pure ordering rule. Out of scope and
not touched: party snapshots, sessions, reference tables, WAL, backup, async
worker, `crates/app`, `crates/cli`, core, schemas and fixtures.

## Implemented
- `crates/storage` (`azeroth-storage`): rusqlite `=0.40.2` with `bundled`, sha2
  `=0.10.9` (already locked). `Cargo.toml` gains one members line; `Cargo.lock`
  gains only new entries (azeroth-storage, rusqlite, libsqlite3-sys,
  hashlink, hashbrown 0.17.1, fallible-iterator, fallible-streaming-iterator,
  vcpkg, sqlite-wasm-rs, rsqlite-vfs); no existing entry changed.
- `migrations`: ordered static `MIGRATIONS`, each applied in one immediate
  transaction together with its `schema_migrations` row; contiguity and gap
  checks; refusal of a newer database (`STORAGE_ERROR`, "Database schema is
  newer than this application") before any write; `migrate_with` (doc-hidden)
  lets tests inject extra or failing migrations.
- `schema_v1.sql`: `schema_migrations`, `profiles`, `profile_preferences`,
  `snapshots`, `snapshot_observations`, `imports`, with foreign keys, CHECK
  constraints on closed vocabularies, UNIQUE(profile, content hash), UNIQUE
  (profile, snapshot id) and a (profile, capture time, sequence) index.
- `ordering::compare_capture` (pure, unit-tested): same session compares
  sequence then session_elapsed_ms; otherwise observed_at only when both
  captures are `ClockTrust::Trusted`; otherwise `Incomparable`. Same position
  is `Same`. Mirrors `observation::freshness` precedence.
- `hash::snapshot_content_hash`: SHA-256 over canonical (sorted-key, compact)
  JSON of the decoded validated envelope, `received_at_utc_ms` removed from
  observation metadata, stored as lowercase hex (`Sha256Hex`). The fixture's
  digest is pinned in a test and was cross-checked with an independent Python
  computation over the same serialized envelope.
- `SnapshotStore` trait (core types and plain crate types only) and
  `SqliteStore`: `import_character_snapshot`, `record_failed_import`,
  `current_snapshot`, `snapshot_history`, `list_profiles`, `set_preference`,
  `preferences`, `delete_profile`; plus `open`, `open_in_memory`,
  `foreign_keys_enabled`, `schema_version`.
- Tests: 10 unit (ordering, FK enforcement, error mapping) and 32 integration
  (`tests/migrations.rs`, `snapshots.rs`, `preferences.rs`, helper
  `tests/common/mod.rs` deriving documents from the committed fixtures).

## Decisions
- Profile identity is (character, edition, build, interface, namespace,
  fixture). The fixture flag is part of the key so a synthetic reference
  snapshot can never displace a real one; this adds `fixture: bool` to the
  lookup (`ProfileKey`) beyond the brief's `(character, context)` signature.
- `ImportOutcome` is `Stored { previous_current: Option<SnapshotId> }`,
  `StoredHistoryOnly { reason: Older | SamePosition | Incomparable }`,
  `Duplicate`. `SamePosition` covers equal sequence/time with different
  content: stored in history, current does not flip.
- A different payload under an already stored snapshot ID in the same profile
  is rejected (`INVALID_INPUT`), never last-writer-wins.
- Only `Newer` replaces current; the first snapshot of a profile is current.
- The full envelope JSON in `snapshots.document` is the source of truth and is
  re-decoded through `decode_envelope` on read; `snapshot_observations` holds
  statuses only so unknown/unsupported/restricted/not_applicable/false are never
  collapsed to NULL or 0.
- `record_failed_import(source, &AppError, received_at)` takes the whole
  `AppError` (code plus its `&'static str` message) rather than only the code.
  `import_character_snapshot` records a failed audit row itself, best effort,
  after rolling back.
- No clock is read: callers pass `received_at`; `schema_migrations` stores a
  name, not an applied-at time. Audit and history pruning use insertion order.
- Retention constants (documented in `model.rs`): history 256 snapshots per
  profile (current never pruned), 1024 audit rows, 1024 profiles, 1024
  preferences per profile, 65 536 observation rows per snapshot, history reads
  limited to 1..=256. Over-limit input is an error, not a silent cut.
- SQLite error text is never forwarded: all failures map to `STORAGE_ERROR`
  with static messages, retryable only for BUSY/LOCKED.
- `tests/common/mod.rs` carries one `#![allow(dead_code)]` because each test
  crate uses a different subset of the shared helpers.

## Limitations
- Synchronous API; the application must call it from a blocking worker.
- Character snapshots only; party snapshots, sessions, dismissals and source
  conflicts (P6/P7/P8 records) are wave 2. No `app_settings` table.
- Not wired into `crates/app` (still demo-only) or the CLI.
- No WAL, no backup, no encryption, no schema downgrade path.
- History pruning drops duplicate-detection memory for pruned snapshots:
  re-importing a pruned old export is stored again as history.
- The canonical hash form is part of the schema contract; changing it needs a
  migration. `Cargo.lock` will conflict with other wave-1 packages at integration.
- Contract follow-up: class/race on `CharacterSnapshot` is not needed here;
  nothing in storage depends on it.
