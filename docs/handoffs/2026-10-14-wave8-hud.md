## Scope and API

Section12.4 now has explicit size/font/contrast/reset/status and safely observed
movement persistence. Pure `HudAppearance` supplies defaults, closed validation,
copy, command parsing, position validation and injected build/combat gate.
Settings DB1 gains additive bounded fields. See
[commands, storage and deferral semantics](../compatibility/HUD_APPEARANCE.md).
Existing false settings and exports survive; future DB layouts remain untouched.

Diagnostics has one latest pending request and distinct requested/last fully
successful application/result states. Recorded build plus successful actual
boolean out-of-combat query precede HUD mutation. Required methods are checked,
getters and operations protected; missing/failed/restricted/unexpected availability
never means safe. Unsupported optional resume-event registration leaves startup
wiring intact. Resume invokes PlanControls refresh with current clock/captured
inputs; it does not replay a stored ready model. Known data/status semantics remain
owned by the existing pure plan evaluator. No new completion mapping is invented.

A local FontString baseline prevents compounding/global mutation. High contrast
uses a closed local palette and optional guarded texture methods. Movement saves
only one actually observed UIParent-relative point, enum anchors and bounded
rounded offsets; no frame references or inferred geometry is persisted.
