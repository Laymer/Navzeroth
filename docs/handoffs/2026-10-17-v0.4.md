# V0.4: SignPath signing for release installers

Owner and sole writer: Claude Code (Opus 5.5); claim [2026-10-17-v0.4](../claims/2026-10-17-v0.4.md).
Baseline main `3b19812`. Branch `feat/V0.4-signpath-signing`. No subagents.

## Changed

- `package-windows.yml`: the signing mode step (tags use `release-signing` when
  `SIGNPATH_ORGANIZATION_ID` is set; a stable tag without it fails; a manual
  `test_signing` run uses `test-signing`). It also uploads the unsigned installer,
  adds the SignPath submit step (pinned `f6d0478`, v3.0) and the verification step,
  all before the install and native smoke tests. Synthetic verifier tests run in
  PowerShell 5.1 and 7. The job gets `actions: read`, and the tag timeout is 170
  minutes so it can wait for manual approval.
- `Signing.ps1`: PE layout parsing, `Assert-SignedFromUnsigned` (signed = unsigned
  bytes except CheckSum and the security entry, plus zero padding and one trailing
  certificate table), and `Assert-AuthenticodeSignature`.
- `Complete-SignedInstaller.ps1`: verify, replace, regenerate `RELEASE_ASSETS.json`
  and `SHA256SUMS.txt`, and re-run `Assert-ReleaseArtifacts`.
- Docs: [CODE_SIGNING.md](../compatibility/CODE_SIGNING.md) (policy, flow, owner
  setup, limitations), plus README and install-guide pointers.

## Checks (actual)

- `Test-Signing.ps1` in Windows PowerShell 5.1 (reached from WSL): 11 checks passed
  (synthetic PE files).
- Real-binary probe (scratch script, not committed): a Valid, timestamped
  vendor-signed `7z.exe` with its signature stripped was accepted as "stripped
  copy + signature" and passed the trusted check. The published 0.9.2 installer
  parses with an empty certificate table, and the signature check reports it NotSigned.
- PowerShell parser: 0 errors in the three new scripts. Workflow YAML parses (js-yaml).
