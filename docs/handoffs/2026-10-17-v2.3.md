# V2.3: RXP guide importer and route replay verifier

Owner and sole writer: Claude Code subagent (Opus 5.5); claim
[2026-10-17-v2.3](../claims/2026-10-17-v2.3.md). Baseline main `1840255`. Branch
`feat/V2.3-guide-verifier`.

## Changed

- `crates/ingest/src/rxp.rs`: inert importer. It scans
  `RXPGuides.RegisterGuide([[ ... ]])` blocks line by line, never runs Lua, and
  parses header tags, `<<` filters (RXP precedence: `!` > space > `/`), steps,
  step tags, 27 directives and notes. Unknown directives, tags, header lines and
  text are kept as unsupported items. Known directives with bad arguments are
  malformed. Structural issues are recorded with their lines. All sizes are
  bounded, and oversize input is refused whole.
- `crates/ingest/src/rxp_verify.rs`: replay verifier ported from `verify2.py`,
  checked against a pluggable `FactSource` trait with typed `Fact<T>`
  (`Known`/`Unknown`) and `QuestRecord` (`Known`/`Absent`/`Unknown`). It covers
  the checks the task names plus objective/reward indexes, coordinates, spell
  training, header hygiene, one edition per guide and file, placeholder text and
  the owner's XP level estimate, which is only used when every input fact is
  known. Statuses: ok, error, warning, unverified, unsupported. A report passes
  only with zero errors, unverified and unsupported findings. `JsonFacts` reads a
  strict `navzeroth-guide-facts` v1 file that names its origin; synthetic facts
  are never marked as evidence.
- `crates/cli/src/guide.rs` and `main.rs`: `guide verify --guide <file> --facts
  <file> [--race R] [--class C]`. It reads files through the existing
  component-checked local boundary and writes the JSON report to stdout. Exit 0
  pass, 1 no pass or refused input, 2 usage.
- `fixtures/guides/synthetic-route.lua` and `synthetic-facts.json`: hand-written,
  every name and number invented. They use every directive and pass.
- Tests: `crates/ingest/tests/rxp.rs` (27 tests) and `crates/cli/tests/guide.rs`
  (6 tests).
- `docs/data/GUIDE_VERIFIER.md`: grammar, checks, facts format, CLI and next step.

## Limitations

- Filter semantics follow the owner's RXP documentation sheet. They have not been
  checked against the RestedXP addon's own parser.
- Step conditions are approximated. `.isQuestComplete` counts "in the log" as
  complete, because objective progress is not modelled. `.maxlevel` and
  `#level` don't skip steps. Edition tokens in filters (`<< tbc`) are unsupported.
- `.line`, `.loop`, `.unitscan`, `.link`, `.skill`, `.reputation`, `.daily` and
  other rarer directives are reported as unsupported rather than interpreted.
  The owner's guide uses none of them.
- Directives with no checkable fact (`.mob`, `.use`, `.collect`, `.vendor`,
  `.home`, `.gossipoption`) produce no finding. They are neither counted as ok
  nor verified.
- `verify2.py` warned past 20 quests and errored past 40. Here the log capacity is
  a fact, and exceeding it is an error.

## Unverified

- Live-client behaviour: whether the addon accepts these guides on the recorded
  Forever build, and real quest, zone and flight-node facts. No local facts file
  exists yet.
- Windows-native runs of the CLI. The read boundary is shared with
  `stage-questiedb`, but this task ran it only on WSL.
