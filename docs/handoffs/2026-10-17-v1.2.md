# V1.2: hybrid delivery contract, gate and receipt CLI

Owner and sole writer: Claude Code (Opus 5.5); claim [2026-10-17-v1.2](../claims/2026-10-17-v1.2.md).
Baseline main `4decacc`. Branch `feat/V1.2-hybrid-delivery`.

## Changed

- `local_data_release.rs`: `DeliveryMode::Hybrid`, valid only in policy format 2
  and only with `local_content` (other modes refuse it). `LocalContent` holds the
  extractor version, native reader revision, profile and metadata hashes, and
  `expected_catalogs` (unique build + locale, `xxYY` locale, digit build, SHA-256
  digest, at most 64). An empty list means not yet declared.
- `receipts.rs`: `sign`/`verify` accept local-catalog and hybrid policies.
  `verify_hybrid` takes the extractor identity from the policy (never from the
  receipt), requires declared digests, and requires the receipt's private catalog
  to be one of them. Helpers for the CLI: strict `read_payload`,
  `read_signature`, `read_secret_key` (64 hex characters, optional newline),
  `assemble` (canonical compact bytes, operator then reviewer) and `public_key_hex`.
- `release-readiness` under a hybrid policy blocks with "no declared expected local
  catalog digests", "requires a signed local-catalog receipt" (at
  `release/v1/local-catalog-receipt.json`, outside the production fingerprint),
  "requires a tested source binding", or the receipt's own verification error. The
  receipt binds the tested commit, like the acceptance evidence.
- CLI: `local-data receipt-public-key | receipt-sign | receipt-assemble |
  receipt-verify`, all of which require every option, read bounded regular files
  only and never print key material.
- The committed `config/release-delivery-v1.json` is unchanged (`bundled_content`).
