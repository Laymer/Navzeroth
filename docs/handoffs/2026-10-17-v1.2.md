# V1.2: hybrid delivery contract, gate and receipt CLI

Owner and sole writer: Claude Code (Opus 5.5); claim [2026-10-17-v1.2](../claims/2026-10-17-v1.2.md).
Baseline main `4decacc`. Branch `feat/V1.2-hybrid-delivery`.

## Changed

- `local_data_release.rs`: `DeliveryMode::Hybrid`, valid only in policy format 2
  and only with `local_content` (other modes refuse it). `LocalContent` holds the
  extractor version, native reader revision, profile and metadata hashes, and
  `expected_catalogs` (unique build + locale, the target's build, `xxYY` locale,
  SHA-256 digest, at most 64, `enUS` required when non-empty). An empty list means
  not yet declared.
- `receipts.rs`: `sign`/`verify` accept local-catalog and hybrid policies.
  `verify_hybrid` takes the extractor identity from the policy (never from the
  receipt), requires declared digests, and requires the receipt's private catalog
  to be one of them. Helpers for the CLI: strict `read_payload`,
  `read_signature`, `read_secret_key` (64 hex characters, optional newline),
  `assemble` (canonical compact bytes, operator then reviewer) and `public_key_hex`.
- `release-readiness` under a hybrid policy blocks with "no declared expected local
  catalog digests", "requires a signed local-catalog receipt" (at
  `release/v1/local-catalog-receipt.json`, outside the production fingerprint),
  "requires a tested source binding", or the receipt's own verification error. The
  receipt binds the tested commit, like the acceptance evidence.
- CLI: `local-data receipt-public-key | receipt-sign | receipt-assemble |
  receipt-verify`, all of which require every option, read bounded regular files
  only and never print key material.
- The committed `config/release-delivery-v1.json` is unchanged (`bundled_content`).

## Independent review

A shell-capable reviewer in an isolated worktree reviewed `67038b7` and found no
blockers. It confirmed by running tests that the hybrid gate blocks in every
missing or invalid case, takes the extractor identity from the policy, binds the
tested commit (ancestry and fingerprint still checked), and never prints keys.

Fixed after review:
- Important 1 (verified by the reviewer): `receipt-assemble` printed a trailing
  newline, so `receipt-assemble > file` produced a receipt that `verify` refused as
  noncanonical. It now writes the exact bytes; the test checks that no trailing
  newline is emitted and verifies the file exactly as written.
- Important 2: "per build and locale" wasn't enforced. Every expected catalog must
  now use the policy target's build, a non-empty list must include `enUS`
  (ADR 0006 §7), and the receipt must match the enUS digest; other locales are
  digests users compare locally.
- Important 3: a readiness test now shows a valid receipt for the tested commit
  clearing every hybrid blocker, and refusals for a receipt bound to HEAD
  (stale), a deDE-only digest and an undeclared digest.
- Optional: `read_small` checks the opened handle and bounds the actual read; the
  public `verify` refuses hybrid policies, so hybrid receipts can only pass through
  `verify_hybrid`.

Recorded, not changed: the readiness report doesn't include the receipt's SHA-256
(audit convenience for V5.4); symlinked parent directories of CLI receipt inputs
are followed (local operator tool).

After the fixes: workspace tests 1,133 passed, 0 failed, 4 ignored; clippy clean.
