# V4.1: daily WoW Forever build watch

Owner and sole writer: Claude Code (Opus 5.5); claim [2026-10-17-v4.1-watch](../claims/2026-10-17-v4.1-watch.md).
Baseline main `920b1e8`. Branch `feat/V4.1-build-watch`. The owner asked for a daily
CI check of the live WoW Forever build.

## Changed

- `scripts/build-watch/lib.mjs` (pure parsing of Blizzard's version tables, watched
  products, known product codes, issue titles), `watch.mjs` (bounded HTTPS fetch,
  JSON report, no writes), `lib.test.mjs` (offline tests).
- `.github/workflows/build-watch.yml`: daily 06:23 UTC and manual; job summary;
  one `build-watch` issue per new product build or new `wow*` product code,
  deduplicated by exact title over open and closed issues. Permissions:
  `contents: read`, `issues: write`. No secrets.
- `ci.yml`: the parser tests run in the `pnpm` job (Linux and Windows matrix).
- Docs: [BUILD_WATCH.md](../compatibility/BUILD_WATCH.md).

## Independent review

No blockers; no injection path found (titles use only validated values, quoted).
Fixed after review: region values are validated (`^[a-z]{2,8}$`, a Region column is
required), so remote Markdown or @-mentions can't reach an issue; more than five
changes in one run become one aggregate issue; recorded titles are read once under
`set -euo pipefail`, so a failed lookup stops the run instead of opening
duplicates; responses are streamed with a byte bound; an empty table for a watched
product fails; versions must end in their build ID. Parser tests: 8 passed; a live run still reports the two baseline titles.
