## Windows fix (2026-10-18)

The required Rust Windows check failed in
`authored_slice_builds_and_verifies_with_solo_and_duo_support` with "Selected
pack path cannot be inspected". The test passes `fs::canonicalize(..)`, which on
Windows returns a verbatim `\\?\C:\...` path. The pack builder's `path_checked`
(`crates/ingest/src/pack.rs`) called `symlink_metadata` on every component prefix,
including the bare `\\?\C:` prefix, which names a volume rather than a directory
entry and cannot be inspected. That was a product bug: a user can select a
verbatim path as well.

- `path_checked` now skips only the `Component::Prefix` step (the local-data
  selection boundary already does this); the root and every later component are
  still inspected, and parent traversal, symlink, reparse-point and ancestor
  checks are unchanged.
- New `path_tests` in `crates/ingest/src/pack.rs`: absolute paths pass, wrong kind
  and `..` are refused (portable); symlinked ancestors stay refused (unix); a
  verbatim canonicalized path passes (windows only). The authored slice test keeps
  `canonicalize`, so on Windows it also covers the verbatim case end to end.
- `.gitattributes` already pins `content/authored/**/*.md` and
  `content/**/*.json` to LF; the slice holds only those two kinds (3 JSON, 14 MD).

Checks run in WSL: `cargo fmt --all --check` clean; `cargo clippy --workspace
--all-targets --exclude azeroth-desktop -- -D warnings` clean; `cargo test
--locked --workspace --exclude azeroth-desktop` all passed. `build-content-v2
--input content/authored/slice-v1` then `verify-pack`: report version 2,
1 dataset, 0 fixtures, 18 files, 67,229 bytes, 34 coverage gaps,

The Windows tests run only on the hosted Rust Windows check of PR #188.

## Review fixes (2026-10-18)

From the independent review of PR #188 (verdict: merge):

- `validate_authored` is now wired into `pack/v2`: `build` runs it right after
  reading `sources.json`, before any catalog bytes are staged, and `inspect`
  (`verify-pack`, `read_verified`) runs it after decoding the catalog. It applies
  whenever the registry has any source with access `authored` and the catalog is
  not a fixture; such a pack must register exactly that one source, so a second,
  non-authored source cannot switch the rules off. The synthetic contract
  fixtures (`fixtures/content-pack/sources.json`) also declare `authored` access
  but carry `fixture: true` catalogs with quests and items, so they stay outside
  the rule; fixture packs are refused by the release gate. New
  `SourceRegistry::iter` in core.
- `pending` now requires `unknown` for every game-fact field (dungeon entrance,
  access, preparation quests, travel edges, rewards; model proficiency and
  layout; map transform). `not_applicable`, `unsupported` and `restricted` are
  refused.
- New `azeroth_core::selection_path::check_prefix`, used by both `path_checked`
  (`crates/ingest/src/pack.rs`) and `checked_path` (`crates/local-data/src/lib.rs`)
  so the two boundaries share one rule: only drive-letter and network-share
  prefixes, plain or verbatim, are accepted. `\\.\...` device namespaces and other
  verbatim prefixes such as `\\?\GLOBALROOT\...` are refused, and a drive prefix
  must be followed by a root, refusing drive-relative `C:foo` and bare `C:` or
  `\\?\C:`. A share root (`\\?\UNC\srv\share`, no trailing separator) is still
  accepted. Limitation: `\\?\Volume{GUID}\...` paths (volumes without a drive
  letter) are refused with the device namespaces; a mounted drive letter or folder
  path is needed.
- The catalog context moved from 70425 to 70450 (reason under Assumptions):
  `catalog.json` (10 occurrences) and `evidence/authoring-statement.md` changed,
  so `party-support.json` has the new `catalog_sha256` and the new
  authoring-statement pin (same byte count) in all 12 rows.

Tests added: `authored_rules_refuse_invented_game_facts_in_build_and_verify`
(`crates/cli/tests/authored_slice.rs`). In it, library `build` and `verify` and
the CLI `build-content-v2` and `verify-pack` all refuse a known reward list with
"Authored content cannot declare a game fact" and leave no output. I disabled each
call site in turn and saw the matching assertion fail. A second, non-authored
source is refused with "Authored pack must declare exactly one source". Also
`game_fact_fields_stay_unknown_not_only_unclaimed`
(`crates/core/tests/content_v2_authored.rs`), and `selection_path` unit tests
(portable, plus a windows-only table). There are windows-only refusal tests in
both `pack.rs` and local-data; the drive-relative cases are skipped when the
working directory is not on a drive letter. The unix symlink test now
canonicalizes its temp root.

Checks run in WSL: `cargo fmt --all --check` clean; `cargo clippy --workspace
--all-targets --exclude azeroth-desktop -- -D warnings` clean; `cargo test
--locked --workspace --exclude azeroth-desktop`: 1224 passed, 0 failed,
4 ignored. `build-content-v2` then `verify-pack` on the committed slice: unchanged

`node scripts/validate-content-v2-schema.mjs`: pass; `pnpm contracts:check`: OK, 73 fixtures. The windows-only tests were
