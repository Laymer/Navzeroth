## Settings refresh-tick bug
Root cause: the load effect depended on `refreshKey`. On every 60 s tick it bumped a generation
counter in render, which made `current` null and unmounted the whole form, and then `setDraft`
replaced the draft with the stored value, so any unsaved text was lost.
Fix (`SettingsScreen.tsx`): a `dirty` ref tracks unsaved edits; a refresh reloads profiles,
parties and the record in the background without blanking the form or disabling the fieldset;
a dirty draft is kept together with the revision it was made against, so saving over a changed
store fails the existing revision check instead of overwriting it. A clean draft still follows
the stored value. A different `client` still clears everything (existing test kept). The
`fixme` in `e2e/refresh-tick.spec.ts` is removed. New unit tests: `SettingsRefresh.test.tsx`.
