# V2.2d: frame-aware partial read of partially encrypted tables

Owner and sole writer: Claude Code subagent (Opus 5.5); claim [2026-10-17-v2.2d](../claims/2026-10-17-v2.2d.md).
Owner approval: 2026-10-17. Baseline `ffd7e65` (PR #185 head); `origin/main`
`8fafc66` (PR #185 merged) was merged in afterwards. Branch `feat/V2.2d-partial-read`.

## Question

V2.2c showed that the 106 tables reported as `unavailable_encrypted_frames` on the
owner's 70450 client (Item, ItemSparse, Map and 103 others) have plain, verified
leading frames, and that their trailing frames are encrypted with unavailable
keys and lie inside DB2 sections whose tact key is non-zero. Can the plain sections
be decoded strictly, with every encrypted range kept as an explicit gap?

## Design

- Native (`native/offline.cpp`; CascLib sources unmodified, OUT_DIR patch below): `nav_casc_frame_count`
  loads frame tables through the public `CascGetFileInfo(CascFileSpanInfo)` and
  counts frames. `nav_casc_frame` reports one frame's logical range from CascLib's
  frame records. For BLTE spans it reads the frame's encoded bytes, checks them
  against the frame-table MD5 (strict) and reports whether the mode byte is `E`.
  An `E` frame is never decoded or decrypted and its bytes are freed at once. `nav_casc_read_at` seeks and
  calls the existing strict `nav_casc_read`.
- `src/native.rs`: on `EncryptedFrames` from the strict whole read, the short
  buffer is dropped and `NativeFile::partial` collects the frame layout and
  strictly re-reads only the plain runs. `Archive::read` now returns
  `Logical::{Whole, Partial}`. Unsafe stays in this module.
- `src/partial.rs` (new, safe): `PartialFile::assemble` checks that the frames
  cover the logical length contiguously, are bounded (at most 2^20 frames) and
  include at least one plain and one encrypted frame. It merges runs and calls
  the reader only for plain runs. It produces the deterministic retained container
  (`NAVZEROTH-PARTIAL-ORIGINAL-V1`: range table plus plain bytes, no encrypted
  bytes) and gap strings `unavailable_encrypted_frames:<first>-<last>:bytes:<offset>+<length>`.
- `src/tables.rs`: the decoder reads through `Input`, a view that returns a slice
  only when it lies inside one verified plain range. Anything else is
  `unavailable_encrypted_frame_range`; nothing is zero-read. A whole file is one
  range, so whole-file behaviour is unchanged apart from two points. Encrypted and
  unavailable section gaps are now one total per reason (`encrypted_section_records:<n>`,
  new `unavailable_frame_section_records:<n>`); before, equal per-section strings
  collapsed when deduplicated. The cell pre-check counts only the
  records of sections that are decoded. Header, field, pallet, common and
  section-directory bytes must be plain. A section whose full extent is not plain
  is skipped whole.
- `src/extraction.rs`: a partial table that decodes is `decoded` with the new
  reason `research_decoded_from_plain_frames`, and its decoded gaps include the
  encrypted runs. If its metadata is in an encrypted frame it is
  `unavailable_encrypted` / `unavailable_encrypted_frames_in_table_metadata`.
  Catalog format, `InventoryDisposition` and the projection format are unchanged
  (no schema change). The projection already carries decoder gaps as
  `<domain>:<table>:<gap>` and marks the domain incomplete. Records of a partially
  available table are therefore identified by table: the gap names the table and
  its encrypted ranges.
- Docs: `docs/data/LOCAL_EXTRACTION.md` has a new "Partial reads" section and an
  updated failure table.

## Follow-up (owner-approved 2026-10-17; review of `5b5e159`)

- **Cell bound** (`9687302`): `tables::MAX_CELLS` raised from 2,000,000 to
  4,000,000, still fixed and documented. A test pins it exactly: 16,000 rows of
  250 cells decode, and 16,001 rows are `decoded_cell_capacity`. Other bounds are
  unchanged: 64 MiB table, 1 million rows, 64 MiB text, 256 MiB output.
- **Never decrypt** (`c5050b1`, review I1): build.rs patches the OUT_DIR copy of
  `CascDecrypt.cpp`, with the retained original still hash-pinned.
  `CascLoadEncryptionKeys` loads nothing, and `CascDecrypt`, the only decrypt
  entry point, treats every key as unavailable. All reads go through it: storage
  open (ENCODING/ROOT, which are read before keys would load anyway), whole reads
  and partial reads. `nav_casc_decryption_disabled` is a run-time self-check:
  1. It checks that a key name from the static table is absent after load.
  2. It adds that name with zero bytes (no key material).
  3. It feeds `CascDecrypt` an `E` frame body and requires `ERROR_FILE_ENCRYPTED`
     with nothing written.
  Every `Archive::open` refuses unless the check passes, and
  `tests/decryption.rs` asserts it. As a negative control I temporarily removed
  the patch: the test then failed.
- **Undecoded partial tables** (`147ce58`, I2): every `Logical::Partial` outcome
  now adds the encrypted-range catalog gaps. A non-decoded one gets reason
  `<reason>:partial_plain_frames`; metadata refusals keep
  `unavailable_encrypted_frames_in_table_metadata`. Unit test in `extraction.rs`.
- **References into undecoded sections** (`93dafca`, O1):
  - a string pointer into a skipped section's pool is `string_in_unavailable_section`;
  - copies rooted at an ID listed for an encrypted section are a gap
    `encrypted_copy_source_records:<n>` and are not materialized;
  - other unresolved copies with an unavailable-frame section are
    `copy_source_in_unavailable_section`.
  The two refusals are `unavailable_encrypted`; genuinely missing sources stay
  `cyclic_or_missing_copy_source`. Synthetic tests cover whole and partial files.
- **Fail closed** (`41f9e83`, O2/O4): `nav_casc_frame` refuses non-strict handles
  and all-zero expected frame MD5s. The comment names the CascLib-internals
  dependency and points to the build.rs pin/hash guard. O3 (strict means per-frame
  encoded MD5 only, no frame-table-vs-EKey check, zero padding of short
  `Z`/raw-ZLIB output) is recorded in `LOCAL_EXTRACTION.md`.

## Limitations

- The native frame functions depend on CascLib internal structures (pinned
  revision `38a3466`). A CascLib update must re-review `offline.cpp`.
- Decryption is disabled by an OUT_DIR patch of CascLib. A CascLib update must
  keep both `replace_once` anchors, or the build fails. The run-time self-check
  refuses archive opens if decryption works.
- A copy whose source may sit in an unavailable-frame section refuses the table:
  that section's IDs are unknown. Strings into skipped pools refuse the table too
  (they are not field-level gaps). Neither occurred on 70450.
- An inconsistent frame layout (not contiguous, not covering, no plain or no
  encrypted frame) is reported as `archive_verification_failed`.
- `unavailable_encrypted_frames` is no longer produced by the read path; the
  mapping is kept for older catalogs.
