## Implemented

- `gear::lua`: internal versioned scoring DTO and pure compiler. Synthetic-only
  source/context/fixture checks; preserves full ItemKey and availability metadata;
  converts raw attributes to integer thousandths with the established Rust rule.
  Caps: 64 candidates, 64 weights, 128 attributes/item, 64 effects/item,
  64 profile notes and 32768 encoded bytes. Rejects mixed context, duplicates,
  live source claims, numeric conversion overflow and budget violations.
- `Core/Gear.lua`: fixed production JSON import, private sorted catalog, exact
  model score components/total, ordered certainty/effect reasons, stable ranking
  of caller-selected sets (128 sets maximum), and complete-certainty comparison.
  Result copies prevent mutation of loaded input. Full key/UTF-8 byte ordering.
- Exact integer multiplication uses base-1000 limbs. Every limb product/carry
  stays small enough for Lua doubles; divide by scale and half-away rounding
  happen before checked conversion back to a safe integer. Raw `toFixed` also
  matches Rust's initial IEEE multiplication/rounding.
- Independent `fixtures/gear-lua/v1` manifest: 10 catalogs, 32 selected-set
  scores and 157 Rust-anchored arithmetic vectors. Core verifies generated
  compilation, every result and arithmetic anchor; two tie fixtures additionally
  match the existing `rank_theoretical` implementation. Lua compares every
  contribution, certainty/status/effect, result/error and ordering exactly.
- Coordinator wrote the sole `gear/mod.rs` export. No exchange schema,
  dependency, lockfile or CI changes. README documents interfaces/limits.

## Decisions, limitations and next task

This is scoring-only data and comparisons; selected sets are caller supplied.

eligibility, legality, acquisition, or practical recommendation. It does not
accept real catalogs/weights or observe equipment. Sources marked synthetic
cannot claim addon/manual/official observations. Unknown/unsupported/restricted/
not-applicable attributes match the existing Rust scorer's low-certainty policy;
modelled zero totals never become complete when attributes are unavailable.
