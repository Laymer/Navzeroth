# V1.1: release manifest schema 2

Owner and sole writer: Claude Code (Opus 5.5); claim [2026-10-17-v1.1](../claims/2026-10-17-v1.1.md).
Baseline main `ae6122b`. Branch `feat/V1.1-manifest-v2`. No subagents.

## Changed

- `crates/core/src/release.rs`: schema 2 adds the required `slice`, per-domain
  `out_of_scope` boundaries and `target: Option<Target>` (key always present,
  `null` = pending, checked in `decode`). `expected_target(schema)` is the code-side
  authority: 70374 for schema 1, `frozen_release_target()` (`None` until V4.2) for
  schema 2. New blockers: "Release target is pending the first stable live build
  after launch (ADR 0006)", "Release slice classes are unknown", "Release slice is
  missing or invalid", and "Out-of-scope boundaries are invalid, duplicated or
  unexplained". Evidence must share the inventory's schema version and target.
  Explicit `upgrade_inventory` / `upgrade_evidence` (v1 to v2).
- CLI: content binds through `release_target()`, which refuses a pending target.
  The binding runs after the pack integrity and fixture checks, so those refusals
  still report. Material selection refuses mixed schema versions and any non-empty
  selection while the target is pending; an empty preview selection still works
  (`target: null` in memory only, no public file).
- `release/v1/*.json` migrated to schema 2 (written with the same JSON layout;
  inventory SHA-256 `5ab72cef…b7cc`, rebound in the evidence). Units keep their IDs
  with slice-scoped text and `null` required records; each domain has one boundary
  for content outside the slice. `classes` is `null` until launch confirms the
  Human class list.
- `Release-Materials.ps1`, `Acceptance-Kit.ps1`: accept schema 1 or 2, with equal
  versions in both manifests.

## Independent review

A shell-capable reviewer in an isolated worktree reviewed head `57e9aee` and found
no blockers. It verified the gates, the duplicate and missing `target` key cases,
the migrated JSON and the material paths by running tests and scripts; the
PowerShell precedence was reasoned only. A first reviewer without shell access
verified nothing and isn't counted. Fixed after review:

- Important 1: a schema 2 domain with an omitted or empty `out_of_scope` now blocks
  ("Out-of-scope boundaries are not declared: <domain>").
- Important 2: CLI tests now cover content under a pending target (material
  selection refused, readiness blocker, zero verified packs), a self-chosen
  schema 2 target, and mixed inventory/evidence versions.
- Optional 3: `release_target()` binds only to `expected_target(schema)`, so a
  self-chosen target can't bind content in the readiness report either.
- Optional 4: fixture and namespace refusals now run before the target binding in
  both pack paths, matching the comment.

Left as recorded optional items: schema 1 decoding accepts an explicit
`"slice": null` / `"out_of_scope": []` (gates unaffected); `assess` relies on
`decode_inventory` for the schema 1 shape; the material manifest keeps
`schema_version: 1` with a nullable `target`, which only reaches stdout or memory.

After the fixes: workspace tests 1,120 passed, 0 failed, 4 ignored; clippy clean.
