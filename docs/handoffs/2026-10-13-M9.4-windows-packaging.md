## Goal and scope

Let Windows users build and install the application and the addon without manual
steps, and give maintainers a reproducible release path (plan M9.4, with the
installation/removal instructions of M9.5). Out of scope: code signing credentials,
release notes for a specific version, auto-update, other platforms.

## Implemented

- `apps/desktop/src-tauri/tauri.windows.conf.json` (merged by Tauri on Windows only):
  bundling on, NSIS, per-user install (no admin), downgrades blocked, WebView2
  bootstrapper if missing, license page, the addon folder and its helper as resources.
- `apps/desktop/src-tauri/windows/installer-hooks.nsh`: a Start-menu shortcut to the
  addon helper; after install, an offer to install the addon (fresh install) or to
  update it in the recorded AddOns folder; before uninstall, an offer to remove it
  through the helper. Silent installs never touch the game folder (`/SD IDNO`).
- `scripts/windows/Install-AzerothNavigatorAddon.ps1`: Install/Uninstall/Status of the
  addon into a user-chosen `AddOns` folder. Refuses non-`AddOns` folders, a running
  game, a different addon with the same folder name and an incomplete source; staged
  copy, SHA-256 verification, rename swap with rollback; records the folder for the
  installer; `-WhatIf`; Windows PowerShell 5.1 and PowerShell 7.
- `scripts/windows/Build-Windows.ps1`: version agreement across the five version
  fields, pinned-toolchain checks with optional winget installation, locked installs,
  optional tests, `tauri build --bundles nsis`, deterministic addon zip, SHA256SUMS,
  clean-tree check, optional signing through `NAVZEROTH_SIGN_COMMAND`.
- `scripts/windows/Test-AddonInstaller.ps1`: 25 checks of the helper against a
  synthetic game folder.
- `.github/workflows/package-windows.yml`: on packaging PRs, dispatch and `v*` tags:
  helper tests (5.1 and 7), build with 5.1, silent install, 20 s first start (SQLite
  store created), silent uninstall, artifact upload; for tags a draft release only.
- Docs: `docs/compatibility/WINDOWS_INSTALL.md` (users, builders, maintainers),
  pointers in `ADDON_INSTALL.md` and `README.md`.

## Decisions

No ADR. NSIS per user over MSI (no admin, uninstall hooks). The addon ships inside the
installer and as a separate zip from the same folder. No AddOns-path guessing (path
unverified, ADDON_INSTALL.md). No auto-updater (needs the publisher trust configuration
of plan §8.7). Tags produce draft releases; publishing stays manual (plan §20.2).
Tauri bundler facts were read from the pinned sources (tauri-cli 2.12.2,
tauri-bundler 2.10.2, tauri-utils 2.10.1): hook macro names, template variables,
`%1` substitution in `signCommand` (whole argument only, string split on spaces),
resource-map directory walking, per-user paths and the "delete app data" behaviour.

## Validation

Local (Linux, PowerShell 7.6.6):

- `Test-AddonInstaller.ps1`: 25/25 checks passed.
- `Build-Windows.ps1 -AddonOnly`: two runs gave the same zip SHA-256;
  `sha256sum -c SHA256SUMS.txt` OK; `-ExpectedVersion v9.9.9` and a mismatched TOC
  version both fail with the expected message.
- PSScriptAnalyzer with `PSUseCompatibleSyntax` for 5.1 and 7.0: no errors
  (remaining warnings: Write-Host in console tools, script-scope parameters).
- Hooks compiled with makensis 3.09 `-WX` in a harness reproducing the template's
  defines, variables and includes.
- Merged Windows config validated against tauri-cli 2.12.2 `config.schema.json`: 0 errors.
- actionlint 1.7.12 (with shellcheck): clean for both workflows.
- All new scripts and the hook file are ASCII (Windows PowerShell 5.1 reads BOM-less
  files as ANSI).

Hosted Windows (windows-2025): see the `Windows package` run on the draft PR; its
result is recorded in the PR description, not assumed here.

Not run: `-InstallPrerequisites` (winget) on a machine without the toolchain; the
interactive installer pages, folder dialog and message boxes; signing; a tag release;
the addon on a live Forever client.

## Limitations

- Unsigned until the owner provides a signing route; SmartScreen warns.
- The Forever AddOns location, TOC interface number and SavedVariables layout remain
  unverified (ADDON_INSTALL.md); the helper relies on the user's choice.
- The game-running check matches any process whose executable lies under the game
  folder; a client started from elsewhere is not detected.
- The zip is byte-identical for the same commit and .NET runtime, not across runtimes.
- The installer requires a 64-bit Windows (x64 target only).
