# R2 selected-file watcher

Owner: Codex worker B, sole writer. Baseline: 08f6daa.
Branch: feature/wave2-r2. Claimed 2026-10-12 before implementation.
Scope: ingest watcher module, export and tests only; no manifests or schemas.
Acceptance: 500 ms polling, 750 ms stable metadata, bounded importer, bounded
partial-write retries, replacement/deletion recovery, cancellation, fixed codes.

## Delivered API and decisions
`azeroth_ingest::watcher::SelectedFileWatcher::new(path, format, options)`;
`poll(elapsed, &Cancellation)` for caller scheduling and deterministic tests;
`run(Cancellation, callback)` for a caller-owned blocking worker. Events contain
fixed snake_case `WatchStatus` and an optional normalized `ImportResult`.
The application decides persistence, duplicate/history-only outcomes and clock
context; watching never claims live observations. Watch only a user-selected path.

Polling is 500 ms; stable size/mtime must last 750 ms (normally imported at the
1000 ms poll). Regular files only. Reads reuse the existing bounded importer,
with bounded byte reads before/after to detect concurrent saves. A metadata or
byte change resets debounce. At most three attempts per unchanged candidate;
a change/deletion/replacement resets the budget. Unchanged successes are not
redelivered. Unix device/inode and portable creation time augment size/mtime
for replacement detection. Cancellation wakes the sleeping worker; a running
bounded parse finishes before termination. Status transitions are deduplicated.

## Limitations and next task
Live client saves and native Windows interaction remain unverified. Metadata
polling cannot detect an in-place edit that restores identical size/mtime and
file identity between polls; byte verification is best effort, not an OS lock.
The existing bounded importer has a metadata/open TOCTOU limitation; no broader
filesystem traversal or import execution was added. Freshness is judged with
the supplied ImportOptions; R3 may refresh this context per watcher lifecycle.
Next dependency-ready task: R3 desktop workflow, consuming this API on its
blocking worker and preserving storage identity/ordering semantics.
