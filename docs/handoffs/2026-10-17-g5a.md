## Goal and scope
Move Today, Atlas, Planner, Gear, Party, Dungeons, Sessions and Reminders (and the panels they
compose: saved plan, route acquisition, route inspection, gear explanations, party planning,
agreement, eligibility, calibration, catalog pager, authored picker, atlas map controls) onto the
G4 primitives and tokens. Files outside the play screens were not edited (`src/ui`, `src/theme`,
`App.tsx` and the data and system screens are untouched).

## What changed
- Every play-screen `<button>` is a `Button` (primary for the main action of a screen, danger for
  deletion and clearing the saved plan, ghost for paging, hide and mark-read, secondary otherwise).
- 45 `Field` uses, most with a HelpTip: planner origin, stopping node, goal, budget, stopping
  service; gear weights, class, proficiency, hands, effort fields; dungeon members, package JSON,
  origin; session text, path, format; reminder profile; atlas search, point type, image; calibration
  conditions; party goal, budget, recipient; route acquisition. Six more HelpTips sit beside checkbox
  rows and groups (outside the labels). Help texts say what an empty or 0 value means and that
  estimates are manual assumptions.
- Panels replace sections that already had a heading at the same level, so region names and the
  heading outline are identical (saved plan, gear rankings, atlas pins, coverage and snapshot
  position, party agreement, joint planning, quest eligibility, calibration, route acquisition).
- `StatusBadge` marks a saved plan as "Matches inputs" or "Historical", next to the unchanged text.
- New `src/screens/play.css`: a translucent slate sheet behind each screen (text no longer sits on
  the backdrop art, addressing G4 review finding 5 for these screens), note styling, inline help
  rows, high-contrast and forced-colours rules. It uses only `--text`, `--tone-warn`, `--gold-hi`
  and `--surface`, all pairs already declared in `tokens.css`, so no new contrast pair was needed
  (and `src/theme` was not edited).
- `Highlight` focus outlines in `atlas.css` and `dungeonPreparation.css` now use `var(--focus)`.
- Existing text, accessible names, roles and test assertions are unchanged; no test file was edited.
  The unknown, stale, restricted, false and zero wording is untouched. One new help text had to avoid
  repeating "Browser demo profiles cannot supply", which an existing test finds by text.

## Limitations / unverified
- Native WebView2 appearance, screen reader behaviour of HelpTip (G4 review finding 2 applies to the
  primitive) and legibility over the backdrop at other viewport sizes are unverified.
- `Button` does not accept `ref` in its types, so the atlas pin button and the route hop buttons
  (which need refs for roving focus) use a native `<button>` with the `ui-button` classes.
- `src/styles.css` (`.demo-label`, `.badge`, party and import label rules) is shared with other
  screens and was not edited; the play screens layer `play-note` on top.
