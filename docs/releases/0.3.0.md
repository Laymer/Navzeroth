# Azeroth Navigator v0.3.0

Windows x64 **developer-preview prerelease**. Delivers manual addon observations
and plan controls, Gear comparisons, Sessions recording/history and Planner route
inspection. New client bindings remain experimental on Forever 1.60.1.70338 /
interface 16001. Full focused-release and live-game acceptance are incomplete.

## Downloads and installation

Prepared artifacts:

- `AzerothNavigator-0.3.0-x64-setup.exe` — per-user desktop installer with addon/helper.
- `AzerothNavigator-addon-0.3.0.zip` — readable Lua addon and BSD-3-Clause license.
- `SHA256SUMS.txt` — integrity hashes for the installer, addon, notes and source record.
- `SOURCE_COMMIT.txt` — exact packaged source SHA.
- `CANDIDATE_NOTES.md` — this version's notes, also included in the checksum list.

Verify hashes before installation. CI downloads expire; permanent release downloads
require subsequent publication. The installer is unsigned unless a signing command
is configured. WebView2 may require a one-time download; installed offline workflows
need no API credentials.

[Windows install/update/remove](https://github.com/Laymer/Navzeroth/blob/release/v0.3.0/docs/compatibility/WINDOWS_INSTALL.md) and
[addon installation](https://github.com/Laymer/Navzeroth/blob/release/v0.3.0/docs/compatibility/ADDON_INSTALL.md). Back up desktop data and
SavedVariables before upgrading. SQLite upgrades existing v4 stores to v5, retaining
snapshots, content and parties while adding immutable session history. Downgrades to
an older application may require restoring a compatible database backup. Close the
game before updating the addon. Keep personal exports private.

## Changes since v0.2.0

- Bounded, guarded manual quest-log reads capture accepted quests and readable
  completion flags. Headers/malformed IDs are diagnosed; partial or oversized reads
  preserve the previous export. Missing quests do not prove turn-in/history.
- Manual equipment capture records readable item identity in numeric inventory
  slots. Missing links remain unknown; variants/instances/modifiers stay unknown.
  Position probes diagnose readability without inventing location/map/floor identity.
- Explicit plan paste/import, show/hide/clear and conservative HUD. Failed replacement
  retains the loaded plan. Expiry, uncertain age, missing dependency checks and
  revalidation remain visible. Plans are runtime-only and reload clears them.
- Acquisition-aware Gear services and screen: current/theoretical/equip-eligible/
  obtainable comparisons, score explanations and conditional practical estimates.
  Weights, categories, proficiencies, slot relationships and effort are manual.
  Practical results require a complete baseline and evaluate one acquisition-backed
  upgrade at a time. Synthetic examples stay labelled; no real tables are invented.
- Separate bounded `ANAVSESSION1:` local transport and immutable session history.
  Exact context/fixture scope, duplicate idempotence, atomic conflict/capacity refusal
  and explicit deletion preserve history. Maximum 128 sessions per profile; no pruning.
- Explicit opt-in session start/sample/pause/resume/stop/export commands. No background
  sampling. Running spans default to unclassified; pauses are gaps. Monotonic reset
  and bounds stop recording; UTC drift warns/revokes UTC trust while sampling continues.
  Manual stop does not claim game logout. Reload never resumes an old timeline.
- Sessions screen imports text/selected files and shows coverage, unclassified spans,
  gaps, observed progression and clock uncertainty separately. Same-profile refresh
  now preserves pending import successes/errors and refreshes resulting history.
- Planner route inspection includes selected legs and the final stopping route.
  Exact-dataset endpoint links are schematic, not road geometry; incompatible spaces
  and missing transforms retain the ordered route with explicit gaps.
- Changed snapshots/dataset revisions invalidate calculations. Minute refresh preserves
  manual Gear/Planner inputs; superseded responses cannot restore old results.

## Manual addon workflow

Choose one anonymous profile ID per character; capture explicitly:

    /anavdiag snapshot anonymous-one

Save through reload/logout, then use desktop Imports with global `AzerothNavigatorDB`
and key `snapshot_export`. Clock trust requires explicit comparison/confirmation;
reload revokes it. Cached captures retain their original timestamp and are labelled.

Export a compatible desktop plan, run `/anavplan paste`, paste the text and press
Import. Use `/anavplan status`, `show`, `hide` or `clear`. Missing authored objective
mappings never complete or advance a step. Capture replacement requires revalidation.

For Sessions:

    /anavsession start anonymous-one
    /anavsession sample
    /anavsession pause
    /anavsession resume
    /anavsession stop
    /anavsession export

Export a stopped recording before reload. Save through reload/logout, then import
`session_export` from `AzerothNavigatorDB` under the matching desktop profile.
SavedVariables are parsed as bounded literals, never executed. Failed export retains
previous successful bytes; new recordings get independent runtime identities.

## Verification and remaining gates

Baseline 0.3.0-rc.1 has a completed
[integration audit](https://github.com/Laymer/Navzeroth/pull/56#issuecomment-6149895403).
New v0.3.0 source requires its own portable Rust, desktop, schema/fixture/content,
Lua, hosted native Windows and package-download checks. Exact new-source results,
SHAs, hashes and download links are attached to the preparation PR after they run.
Hosted install/first-start/uninstall smoke and command-mock browser checks remain
separate from native user interaction and actual game behavior.

Earlier user reports cover one correct level 12 import and trusted/uncertain capture
age behavior, under limited recorded conditions. No new live quest, equipment, plan
paste/HUD or session evidence is supplied. Run the
[v0.3.0 live checklist](https://github.com/Laymer/Navzeroth/blob/release/v0.3.0/docs/compatibility/V030_LIVE_CHECKLIST.md) on the recorded build.

Real playable content, validated quest-stage mappings, verified road geometry,
joint planning, party messaging, calibration, representative live performance,
interactive native dialogs and bare-machine setup remain unverified or deferred.
No memory access, injection, packet decoding, input automation or addon socket bridge.
External LFS imagery is not packaged; bundled demonstration imagery is synthetic.
The existing Linux GTK transitive advisory remains recorded in STATUS; no dependency
upgrade is part of this release preparation. Schemas/SavedVariables layout remain v1;
local SQLite schema is v5. Missing environment checks are not counted as passed gates.
