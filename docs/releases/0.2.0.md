# Azeroth Navigator v0.2.0

Windows x64 **developer-preview prerelease**. Includes a bounded manual character
snapshot producer and explicit capture-clock verification. One user reported a
correct level-12 snapshot import on Forever 1.60.1.70338 / interface 16001.
Equipment, quests, position, actual clock behavior and live planning remain unverified.

## Downloads

- AzerothNavigator-0.2.0-x64-setup.exe — per-user desktop installer, addon and helper.
- AzerothNavigator-addon-0.2.0.zip — standalone readable Lua addon and BSD license.
- SHA256SUMS.txt — integrity checks for both downloads.

The Windows installer is unsigned. WebView2 may require a one-time download.
After installation the companion operates offline without API credentials.
[Install/update/remove instructions](https://github.com/Laymer/Navzeroth/blob/v0.2.0/docs/compatibility/WINDOWS_INSTALL.md).
Keep application/SavedVariables backups when testing prerelease updates.

## Changes since v0.1.0

- Explicit /anavdiag snapshot <anonymous-profile-id> captures level on the recorded
  70338 client tuple; other fields stay unknown or absent. Unique anonymous IDs and
  persisted capture sequences preserve profile/ordering boundaries.
- Separate snapshot_export ANAV1 text with bounded encoding and conservative
  source/fixture checks. Desktop SavedVariables import defaults are
  AzerothNavigatorDB / snapshot_export; paths and keys remain user-selectable.
- User-reported level-only capture/import evidence is recorded separately from
  synthetic tests and API-presence findings. The older 70205 dataset is unchanged.
- /anavdiag clock inspects guarded UTC/monotonic samples. Only after checking against
  trusted UTC should the operator run /anavdiag clock trust within 120 seconds.
  Subsequent snapshots can carry trusted UTC capture time; without confirmation
  they stay uncertain. Reload, bad reads, reversals and clock jumps clear trust.
- Lua loaded-plan advancement from fresh positive objective completion, participant
  isolation, stable declared alternatives and explicit revalidation. Alternatives
  cannot rewrite global travel and require travel revalidation.
- Version agreement checks now include the addon Lua version as well as manifests/TOC.

## Using snapshot capture and timing

Close the game while updating the addon. Choose one unique anonymous ID per character:

    /anavdiag snapshot anonymous-one

Reload or log out, then select AzerothNavigator.lua in desktop Imports and choose
SavedVariables export string, global AzerothNavigatorDB, key snapshot_export.
The diagnostic_export report remains separate and is not a character snapshot.

To verify timing, first run:

    /anavdiag clock

Compare the printed epoch seconds with a trusted UTC source, for example Windows
PowerShell:

    [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()

Only if they agree, run /anavdiag clock trust within 120 seconds and capture again.
Trust applies to the current addon runtime and resets on reload. UTC API presence
or a timestamp by itself does not grant trust. Missing/failed clocks preserve the
level capture flow with uncertain freshness. Engineering guards allow a two-second
sample span and five-second UTC/monotonic disagreement; they are not game facts.
[Detailed instructions](https://github.com/Laymer/Navzeroth/blob/v0.2.0/docs/compatibility/ADDON_INSTALL.md#capture-timing-in-v020).

## Verification and limits

The level-only flow has one user-reported positive result (level 12) on 70338,
English client language; region-specific locale code remains unknown.
Clock availability/behavior and the new confirmation flow are not yet live-verified.
Do not interpret this release as full M0/M2 acceptance or verified gameplay planning.

Release preparation requires Rust/TypeScript/Lua/contract/browser checks and native
Windows builds. Tag packaging tests PowerShell 5.1/7, builds the installer, exercises
silent install, first start/store creation, uninstall and retained user/addon data.
Final run links and downloaded artifact checks are added to the GitHub release after
actual completion.

- No real playable quest/acquisition catalog, verified route/map transforms, live
  plan import UI, joint planning, or desktop gear/session screens.
- No elapsed gameplay-session time is inferred from the persistent capture stream.
- Interactive native dialogs, bare-machine setup, signing and live addon/HUD
  performance remain unverified. Source has the previously documented Linux GTK
  transitive glib advisory GHSA-wrw7-89jp-8q8g; Windows does not use that dependency.
- Synthetic examples remain labelled. External LFS atlas imagery is not packaged.
- Schemas and SavedVariables layout remain v1, with additive snapshot keys.
- No memory access, injection, packet decoding, input automation or addon socket bridge.
